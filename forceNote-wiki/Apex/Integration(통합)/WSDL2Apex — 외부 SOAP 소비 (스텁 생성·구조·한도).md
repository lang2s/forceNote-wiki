# WSDL2Apex — 외부 SOAP 소비 (스텁 생성·구조·한도)

> 외부 SOAP 서비스(ERP 등)의 WSDL을 Setup에서 **가져와 Apex 스텁 클래스를 자동 생성**해 콜아웃하는 정방향 통합이다. Apex 메서드를 SOAP로 *노출*하는 [[SOAP Web Services 노출 (webservice 키워드)]]와 반대 방향 — 여기서는 Salesforce가 **소비자(client)** 다.

---

## 방향 구분 — 노출 vs 소비

| 방향 | 도구 | 시작점 | 이 노트 |
|---|---|---|---|
| Apex를 SOAP로 **노출** (Salesforce = 서버) | `webservice` 키워드 → WSDL 생성 | Apex 클래스 | [[SOAP Web Services 노출 (webservice 키워드)]] |
| 외부 SOAP를 **소비** (Salesforce = 클라이언트) | **Generate from WSDL** → Apex 스텁 생성 | 외부 WSDL 파일 | ✅ 이 노트 |

> 참고: 공식 문서는 "가능하면 콜아웃보다 Outbound Messaging을 쓰고, 서드파티 콜아웃은 꼭 필요할 때만 사용하라"고 권한다.

## Setup 워크플로우 — Generate from WSDL

```
1. Setup → Quick Find "Apex Classes" → Apex Classes
2. [Generate from WSDL] 클릭
3. [Browse]로 로컬 하드/네트워크의 WSDL 지정 (또는 전체 경로 입력)
4. [Parse WSDL] — 네임스페이스마다 기본 클래스명을 생성하고 오류를 보고
5. 클래스명 수정 (선택) — 여러 네임스페이스를 같은 클래스명으로 한 클래스에 합칠 수 있으나 클래스당 100만 자 한도
6. [Generate Apex] — 성공/실패 클래스 목록과 생성 코드 링크 표시
```

**아웃바운드 포트 제한** — WSDL의 SOAP endpoint가 아웃바운드 포트를 참조하면, 보안상 다음만 허용된다:

| 포트 | 허용 프로토콜 |
|---|---|
| `80` | HTTP만 |
| `443` | HTTPS만 |
| `1024–66535` (inclusive) | HTTP 또는 HTTPS |

각 생성 클래스에는 **같은 이름 + `Async` 접두사**의 두 번째 클래스가 함께 만들어진다. 첫 번째는 동기 콜아웃용, `Async*`는 비동기 콜아웃(Continuation)용이다.

생성 시 Apex 명명 규칙 적용:
- WSDL에 Apex 예약어가 있으면 `_x`가 붙는다 (예: `limit` → `limit_x`).
- 출력 메시지에 element가 2개 이상이면 inner class로 래핑하고, 메서드는 그 inner class를 반환한다.
- Apex 클래스명에 마침표(`.`)를 못 쓰므로 WSDL 이름의 `.`은 `_`로 치환된다.

## 생성 스텁 클래스 구조 (전수) — docSample 예

공식 샘플 WSDL(operation `EchoString`, 네임스페이스 `http://doc.sample.com/docSample`)에서 생성되는 클래스는 아래 구조다. 클래스명 `docSample`은 import 시 지정한 이름이다.

```apex
//Generated by wsdl2apex
public class docSample {
    // 응답 래퍼: 응답 complexType → 클래스, 각 element → public 필드
    public class EchoStringResponse_element {
        public String EchoStringResult;
        // (직렬화 메타: *_type_info, apex_schema_type_info, field_order_type_info)
    }
    // 요청 래퍼: 요청 complexType → 클래스
    public class EchoString_element {
        public String input;
    }
    // 스텁(포트) 클래스 — WSDL port 이름이 스텁 클래스로 매핑
    public class DocSamplePort {
        public String endpoint_x = 'http://YourServer/YourService';
        public Map<String,String> inputHttpHeaders_x;
        public Map<String,String> outputHttpHeaders_x;
        public String clientCertName_x;
        public String clientCert_x;
        public String clientCertPasswd_x;
        public Integer timeout_x;
        private String[] ns_map_type_info = new String[]{
            'http://doc.sample.com/docSample', 'docSample'};
        // WSDL operation → public 메서드
        public String EchoString(String input) {
            docSample.EchoString_element request_x = new docSample.EchoString_element();
            request_x.input = input;
            docSample.EchoStringResponse_element response_x;
            Map<String, docSample.EchoStringResponse_element> response_map_x =
                new Map<String, docSample.EchoStringResponse_element>();
            response_map_x.put('response_x', response_x);
            WebServiceCallout.invoke(
                this, request_x, response_map_x,
                new String[]{endpoint_x,
                    'urn:dotnet.callouttest.soap.sforce.com/EchoString',
                    'http://doc.sample.com/docSample', 'EchoString',
                    'http://doc.sample.com/docSample', 'EchoStringResponse',
                    'docSample.EchoStringResponse_element'});
            response_x = response_map_x.get('response_x');
            return response_x.EchoStringResult;
        }
    }
}
```

### 네임스페이스 → 클래스 매핑 규칙

| WSDL 구성요소 | Apex 매핑 |
|---|---|
| target namespace | **Apex 클래스명** (스키마 targetNamespace → 부모 클래스) |
| 각 complexType / simpleType | 클래스 (부모 WSDL 클래스 안의 inner class) |
| complexType 내 각 element | 그 클래스의 public 필드 |
| WSDL port 이름 | **스텁 클래스** (예: `DocSamplePort`) |
| 각 operation | 스텁 클래스의 **public 메서드** |
| WSDL에 정의된 SOAP 헤더 | 스텁의 public 필드 (AJAX Toolkit·.NET과 동일 방식) |

### 스텁 특수 필드 (`_x`)

| 필드 | 타입 | 용도 |
|---|---|---|
| `endpoint_x` | `String` | 콜아웃 대상 URL. Named Credential 사용 시 `'callout:My_NC'` |
| `timeout_x` | `Integer` | 콜아웃 타임아웃(밀리초). 기본 10초, 최소 1ms, 최대 120,000ms |
| `inputHttpHeaders_x` | `Map<String,String>` | 요청 HTTP 헤더 설정 (지정 시 표준 헤더를 **덮어씀**) |
| `outputHttpHeaders_x` | `Map<String,String>` | 응답 HTTP 헤더 접근. 기본 `null` — 콜아웃 **전에** 초기화해야 응답 헤더에 접근 가능 |
| `clientCertName_x` | `String` | 양방향(mutual) 인증용 인증서의 **Unique Name** |
| `clientCert_x` / `clientCertPasswd_x` | `String` | 인증서 본문/비밀번호 (레거시; Java keystore 저장 권장) |

## 호출 예제

```apex
// 1) 스텁 인스턴스 생성 → 2) endpoint 설정 → 3) 메서드 호출
docSample.DocSamplePort stub = new docSample.DocSamplePort();
String input = 'This is the input string';
String output = stub.EchoString(input);
```

**타임아웃 지정**

```apex
docSample.DocSamplePort stub = new docSample.DocSamplePort();
stub.timeout_x = 2000; // 밀리초 (최대 120000)
```

**HTTP 헤더 (Basic 인증·쿠키·커스텀 헤더 — Named Credential 권장)**

```apex
docSample.DocSamplePort stub = new docSample.DocSamplePort();
stub.inputHttpHeaders_x = new Map<String, String>();
stub.inputHttpHeaders_x.put('Authorization', 'Basic QWxhZGRpbjpvcGVuIHNlc2FtZQ=='); // Tip: 대신 Named Credential 사용
stub.inputHttpHeaders_x.put('Cookie', 'name=value');
String output = stub.EchoString('...');

// 응답 헤더 읽기 — 콜아웃 전에 초기화 필수
stub.outputHttpHeaders_x = new Map<String, String>();
output = stub.EchoString('...');
String cookie = stub.outputHttpHeaders_x.get('Set-Cookie');
```

**양방향 인증서 (2-way auth)** — 인증서의 Unique Name을 `clientCertName_x`에 대입:

```apex
docSample.DocSamplePort stub = new docSample.DocSamplePort();
stub.clientCertName_x = 'DocSampleCert'; // Certificate and Key Management의 Unique Name
String output = stub.EchoString('...');
```

## 지원 스키마 — document literal wrapped **전용**

> Apex는 **document literal wrapped WSDL 스타일만** 지원한다. RPC/encoded는 지원하지 않는다.

지원 primitive/built-in 데이터타입 (Schema Type → Apex Type):

| Schema Type | Apex | Schema Type | Apex |
|---|---|---|---|
| `xsd:anyURI` | String | `xsd:NOTATION` | String |
| `xsd:boolean` | Boolean | `xsd:positiveInteger` | Integer |
| `xsd:date` | Date | `xsd:QName` | String |
| `xsd:dateTime` | Datetime | `xsd:short` | Integer |
| `xsd:double` | Double | `xsd:string` | String |
| `xsd:float` | Double | `xsd:time` | Datetime |
| `xsd:int` | Integer | `xsd:token` | String |
| `xsd:integer` | Integer | `xsd:unsignedInt` | Integer |
| `xsd:language` | String | `xsd:unsignedLong` | Long |
| `xsd:long` | Long | `xsd:unsignedShort` | Integer |
| `xsd:Name` / `xsd:NCName` | String | `xsd:normalizedString` | String |
| `xsd:nonNegativeInteger` | Integer | `xsd:NMTOKEN` / `xsd:NMTOKENS` | String |

지원 스키마 construct: `xsd:all`, `xsd:annotation`, `xsd:attribute`, `xsd:choice`, `xsd:element`(API 15.0+; `ref`는 제약 있음 — 다른 네임스페이스 ref 불가·global element는 ref 불가·`ref`와 `name`/`type` 동시 불가), `xsd:sequence`.

**call-in 전용(콜아웃 미지원)** — 외부→Apex 웹서비스 호출 때만 지원, Apex→외부 콜아웃엔 미지원: `blob`, `decimal`, `enum`.

`anyType`: API 15.0+ 미지원(14.0 이하는 String 매핑).

## 미지원 / 한도 → 파서 거부

Apex가 지원하지 **않는** WSDL construct·타입·서비스:

| 미지원 대상 | 결과 / 비고 |
|---|---|
| **RPC/encoded services** | parse 실패 (document literal만 지원) |
| **multiple portTypes / services / bindings** (2개 이상) | parse 실패 |
| **외부 스키마 import** (`<xsd:include schemaLocation="...">`) | parse 실패. 단 **같은 스키마 내 import**(외부 WSDL을 변환 대상 안에 붙여넣기)는 지원 |
| document literal wrapped가 **아닌** WSDL | `"Unable to find complexType"` 오류 — simpleType을 element sequence를 담은 complexType로 래핑하면 해결 |
| 표에 없는 스키마 타입 | parse 실패 |
| 크기 초과 WSDL (예: Salesforce SOAP API WSDL) | parse 실패 |

> ⚠️ 위 표에서 정확한 문구가 확인된 파서 오류는 non-document-literal-wrapped의 **`"Unable to find complexType"`** 하나다. 나머지 미지원 construct는 parse 단계에서 거부되며 정확한 메시지는 WSDL 내용에 따라 다르다.

**1,000,000자(1 million characters) 한도 — 생성 클래스 크기**

- Parse는 결과 Apex 클래스가 **클래스당 100만 자** 한도를 넘으면 실패한다.
- 여러 WSDL 네임스페이스를 **같은 클래스명**으로 한 클래스에 합칠 수 있으나 합쳐도 클래스당 100만 자를 넘을 수 없다.
- **공식 우회:** 네임스페이스별로 **서로 다른 클래스명을 지정해 2개 이상 클래스로 분산**하면 각 클래스가 100만 자 한도 안에 들어간다. 또한 WSDL2Apex 도구는 오픈소스(GitHub)라 로컬에서 생성 후 붙여넣을 수도 있다.
- 테스트용 mock 클래스(`@isTest` + `WebServiceMock` 구현)는 org 코드 6MB 크기 한도에서 제외할 수 있다.

## Enterprise / Partner / 커스텀 WSDL 구분

Salesforce 자체가 배포하는 Enterprise/Partner WSDL은 **크기 초과로 parse 불가**(SOAP API WSDL은 소비할 수 없음). WSDL2Apex는 서드파티(ERP 등)나 `webservice` 키워드로 노출한 **커스텀 Apex 클래스 WSDL** 소비에 쓴다.

## Considerations (요약)

- 네임스페이스를 SOAP 요청 안에서 바꿔야 하는 WSDL은 스텁 대신 **HTTP POST로 SOAP body를 직접 구성**해 호출한다.
- 변수명 미지원 문자 규칙: 첫 글자가 비알파벳이면 앞에 `x`, 마지막 문자가 부적합하면 뒤에 `x`, 중간 부적합 문자는 `_`로 치환(연속 부적합 문자는 `_`+`x`). `a_`와 `a_x` 두 파라미터는 둘 다 `a_x`로 충돌 → 컴파일 실패, 수동 수정 필요.
- 런타임 검사: 순환 참조 금지, loopback 연결 1개 초과 금지, endpoint는 Remote Site Settings 등록 필요, 열린 트랜잭션 없어야 함.
- 디버깅: SOAP API의 DebuggingHeader로 요청/응답 XML 확인.

## 콜아웃 한도 (SOAP·HTTP 공통)

- 트랜잭션당 최대 **100 콜아웃**. Developer Edition은 org 도메인 밖 endpoint에 **동시 20 콜아웃** 제한.
- 타임아웃: 기본 **10초**, 콜아웃당 최소 1ms·최대 **120,000ms**, 트랜잭션 누적 최대 **120초**.
- pending DML/비동기(future·batch·queueable)·이메일이 있으면 콜아웃 차단 → 콜아웃을 먼저 수행.
