# 스킬 ↔ 위키 토픽 맵 (디스패처)

> 실행형 질문에서 "주제 → sf-skill(실행) + 위키 노트(검증된 패턴)"를 한 표에서 라우팅하는 디스패처 — 다방향 정보 접근.

---

## 사용법

질문을 받으면 먼저 **의도를 분기**한다.

- **지식 질문** ("X가 뭐야 / 어떻게 동작해 / 차이가 뭐야") → 📘 **위키 우선**. `00 SEARCH_INDEX` → 도메인 샤드 → 패턴 노트로 답한다.
- **실행형 질문** ("만들어줘 / 생성 / 배포 / 스캐폴딩 / 마이그레이션 / 분석해줘") → 이 표에서 **주제 → 대응 sf-skill**을 찾아 안내한다.

> [!note] 현재 스킬 미설치 — 안내 모드
> 이 위키 환경에는 sf-skill이 설치되어 있지 않다. 따라서 이 표의 ⚙️ sf-skill 칸은 **"이런 실행 스킬이 존재한다"는 안내**이며, 직접 호출/실행하지 않는다. 실제 실행은 사용자 환경에서 해당 스킬을 설치한 뒤 수행한다. 위키는 그 실행이 따라야 할 **검증된 패턴(📘)**을 제공한다.

**출처 라벨을 항상 분리한다:**

| 라벨 | 의미 | 신뢰 |
|---|---|---|
| 📘 위키 | 공식 PDF/소스 기반 검증된 패턴 노트 | 정본 (Tier 1/2) |
| ⚙️ sf-skill | 코드/메타를 실제로 생성·배포·분석하는 실행 스킬 | 실행 도구 (안내만) |

```text
// 구조 예시 — 실제 동작 코드 아님 (질문 → 라우팅 흐름)
질문: "테스트 클래스 좀 만들어줘"
  ├─ 의도 = 실행형(만들어줘)
  ├─ 주제 = Apex 테스트
  ├─ ⚙️ sf-skill  → platform-apex-test-generate  (실행: TestDataFactory·mock·bulk 생성)
  └─ 📘 위키      → [[Apex/Testing(테스트)/테스트 전략]] · [[Apex/Testing(테스트)/StubProvider]]
                     (검증된 패턴: 무엇을 어떻게 테스트할지)
응답 = "이 스킬이 생성을 담당, 이 위키가 따라야 할 패턴" 양쪽 제시
```

**겹침 강도:** 강 = 같은 주제/같은 API(직접 cross-link) · 중 = 인접·부분 겹침 · 약 = 느슨한 연관.
