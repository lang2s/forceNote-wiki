# 필드 타입 선택 가이드 (어드민 빌드 관점)

> 어드민이 Setup에서 커스텀 필드를 만들 때 **"어떤 타입을 고르나"**를 결정하는 가이드. 각 타입의 용도·크기·주의(변경 불가·전환 제약·인덱싱)를 담는다. API/WSDL 관점(anyType·calculated 등)은 다루지 않고 [[Field Types]]에 위임한다.

---

## 이 노트의 범위 — 빌드 관점 vs API 타입 관점

같은 "필드 타입"이라도 두 시점이 다르다. 이 노트는 **어드민 빌드(Setup → New Custom Field)** 시점이다.

| 관점 | 어디서 보나 | 다루는 노트 |
|---|---|---|
| **어드민 빌드 타입** (Text·Picklist·Lookup·Formula…) | Setup의 필드 생성 마법사에서 고르는 타입 | **이 노트** |
| **API/WSDL 데이터 타입** (`string`·`double`·`reference`·`calculated`·`anyType`…) | `DescribeSObjectResult.fields[].type` | [[Field Types]] |

> 예: 어드민이 만드는 Text·Email·Phone·Picklist·URL은 모두 API에서 `string`으로, Currency·Number·Percent·Roll-Up은 `double`로, Lookup·Master-Detail은 `ID`(`reference`)로 나타난다. 매핑 상세는 [[Field Types]]의 "Salesforce 앱과 API의 필드·타입 차이" 표.

> [!note] Setup 라벨 캐비엇 (2026-07-12 기준)
> 아래 타입명·마법사 라벨은 help.salesforce.com "Custom Field Types" 기준이다. Salesforce는 릴리스마다 Setup UI 문구를 조정하므로 실제 org의 라벨과 세부 표기가 다를 수 있다. 크기·제약 수치는 접속일 기준 공식 문서 값이다.

## 텍스트 계열 — Text vs Text Area vs Long Text Area vs Rich Text

가장 흔한 선택 갈림길. **크기·줄 수·검색/필터 가능 여부·포맷(HTML)**으로 갈린다.

| 타입 | 최대 크기 | 줄 | 포맷 | 언제 쓰나 / 주의 |
|---|---|---|---|---|
| **Text** | 255자 | 한 줄 | 없음 | 이름·코드·짧은 식별자. SOQL WHERE 필터·정렬 가능. External ID·Unique 지정 가능(인덱싱) |
| **Text Area** | 255자 | 여러 줄 | 없음 | 짧은 메모(줄바꿈 필요). 255자 한도는 Text와 동일 |
| **Text Area (Long)** | **131,072자** | 여러 줄 | 없음 | 긴 설명·본문. **WHERE 필터 불가**(API `textarea`) → 필터가 필요하면 Text 사용 |
| **Text Area (Rich)** | **131,072자** (포맷·HTML 태그 포함) | 여러 줄 | HTML(굵게·밑줄·목록·이미지) | 서식/이미지가 필요한 본문. 저장 용량에 HTML 태그가 포함돼 실제 텍스트는 그만큼 줄어듦 |

> 원문: *"Text Area (Long) displays multi-line text input for up to 131,072 characters"* / *"Text Area (Rich) displays rich text ... for up to 131,072 characters including the formatting and HTML tags."*

**선택 규칙:**
- 한 줄 + 필터/정렬/인덱싱 필요 → **Text**
- 여러 줄 짧은 메모 → **Text Area**
- 긴 본문(필터 불필요) → **Long Text Area**
- 서식·이미지 필요 → **Rich Text Area**

## 숫자 계열 — Number vs Currency vs Percent

셋 다 API에서 `double`이지만 **표시·통화 연동**이 다르다.

| 타입 | 용도 | 표시 | 주의 |
|---|---|---|---|
| **Number** | 순수 수치(수량·개수) | 숫자 그대로 | 소수 자릿수 지정 |
| **Currency** | 금액 | 통화 기호 | **멀티 통화 활성 org**에서는 레코드의 `CurrencyIsoCode`에 연동 — [[Multiple Currencies (멀티 통화)]] 참조 |
| **Percent** | 백분율 | 값 뒤 `%` | 0.5가 아니라 **50**을 저장(50%) — Number로 비율 계산 시 혼동 주의 |

## 선택 계열 — Picklist vs Multi-Select Picklist (안티패턴 주의)

| 타입 | 선택 | 저장 형태 | 언제 쓰나 |
|---|---|---|---|
| **Picklist** | 하나 | 단일 값 | 상호 배타적 값(상태·단계) |
| **Picklist (Multi-Select)** | 여럿 | **세미콜론(`;`) 구분 문자열** | 여러 값 동시 선택 |

> [!warning] Multi-Select Picklist는 안티패턴이 되기 쉽다
> - 값이 `;`로 이어진 한 문자열로 저장 → **리포트 필터·SOQL 필터가 까다롭다**(`INCLUDES`/`EXCLUDES` 필요, 정확 매칭 어려움).
> - 롤업·수식·정렬·그룹화에 약하다.
> - 여러 값을 "제대로" 다뤄야 하면 **junction 오브젝트(다대다 관계)** 나 **자식 레코드**가 정석이다 — [[Object Relationships]]의 many-to-many 참조.
> - Multi-Select는 "가볍게 태그 몇 개" 수준일 때만.

> [!note] Picklist ↔ Text 전환
> Text → Picklist 변환이 지원된다(값이 자동으로 피클리스트 값이 됨). 반대로 Picklist → Multi-Select 변환 시 **기존 정의된 값은 유지되나, 피클리스트 정의에 없는 값을 가진 레코드는 그 값이 삭제된다.** (아래 "타입 전환 시 데이터 손실" 참조)

관리·종속·글로벌 값 세트는 [[Picklists — Global Value Sets & Dependent Picklists (피클리스트)]] 참조.

## Checkbox (Boolean)

- 참/거짓 두 값. API에서 `boolean`.
- 기본값을 checked/unchecked 중 지정.
- 리포트·수식·자동화 조건에서 다루기 가장 쉬운 타입 → **"예/아니오" 플래그**엔 Picklist보다 Checkbox.

## 날짜·시간 계열 — Date vs Date/Time vs Time

| 타입 | 저장 | 언제 쓰나 |
|---|---|---|
| **Date** | 날짜만 | 생일·마감일 등 시각이 불필요할 때 |
| **Date/Time** | 날짜 + 시각(타임존 변환됨) | 이벤트 발생 시각 등 시각이 중요할 때 |
| **Time** | 시각만(날짜 무관) | 영업 시작 시각 등 매일 반복되는 시각 |

> Date/Time은 사용자 타임존으로 변환 표시되고, Date는 변환 없이 그대로 보인다 — 시각 정밀도가 필요 없으면 Date가 혼란이 적다.

## 포맷 검증 계열 — Email vs Phone vs URL

세 타입 모두 API에서 `string`이지만 **입력 형식/표시**가 다르다.

| 타입 | 특징 |
|---|---|
| **Email** | 이메일 형식 필드. UI에서 mailto 링크·간단한 형식 확인 |
| **Phone** | 전화번호 형식. 문자(`1-800-FLOWERS`) 포함 가능, 로케일 포맷팅 |
| **URL** | UI에서 클릭 가능한 하이퍼링크로 표시 |

> 세 타입은 UI 편의(링크·포맷)를 제공하지만 **완전한 형식 검증기는 아니다** — 엄격한 검증이 필요하면 Validation Rule을 함께 건다. (API 관점 email/phone/url의 검증 책임은 [[Field Types]] 참조)

## 계산 필드 — Formula vs Roll-Up Summary (계산 위치가 다름)

**"값을 어디서 계산하나"** 로 갈린다.

| 타입 | 계산 위치 | 무엇을 계산 | 정의 위치 |
|---|---|---|---|
| **Formula** | **같은 레코드**(+ 부모 참조) | 동일 레코드 필드나 부모 필드로 파생값 | 어느 오브젝트든 |
| **Roll-Up Summary** | **자식 레코드 집계** | 자식 레코드의 COUNT·SUM·MIN·MAX | **master-detail의 master(부모) 오브젝트** |

> 원문(Formula): *"Because formula fields are automatically calculated, they are read-only on record detail pages and do not update last modified date fields."*
> 원문(Roll-Up): *"You can count the number of detail records related to a master record, or you can calculate the sum, minimum value, or maximum value of a field in the detail records. Roll-up summary fields are defined on the object that's on the master side of a master-detail relationship."*

- **Formula**: 읽기 전용(상세 페이지). 편집 페이지엔 안 나타남. 자세히 → [[Formula 필드]]
- **Roll-Up Summary**: **master-detail 관계가 전제** (Lookup으론 불가). 자세히 → [[Roll-Up Summary 필드]]

> 규칙: "이 레코드의 다른 값으로 계산" → Formula / "자식들을 합·개수" → Roll-Up Summary(관계가 master-detail이어야 함).

## 관계 필드 — Lookup vs Master-Detail vs Hierarchy

관계 필드는 API에서 `ID`(`reference`)다. 세부 개념(공유·삭제 전파·다대다)은 [[Object Relationships]]에 위임하고, 여기선 **빌드 선택 기준**만 정리.

| 타입 | 결합도 | 특징 / 언제 쓰나 |
|---|---|---|
| **Lookup Relationship** | 느슨 | 부모 삭제해도 자식 유지(옵션). 독립적 두 오브젝트를 연결 |
| **Master-Detail Relationship** | 강함 | 자식은 부모에 종속(부모 삭제 시 자식 삭제·공유 상속). **Roll-Up Summary의 전제** |
| **Hierarchy** | 자기참조 | **User 오브젝트 전용** 자기참조 관계(관리자 계층 등) |

> [!note] Master-Detail 생성 제약
> 원문: master-detail 옵션은 *"available for custom objects only when the custom object doesn't already have a master-detail relationship."* — 커스텀 오브젝트당 이미 master-detail이 있으면 추가 불가(오브젝트당 최대 2개까지가 일반적 한도). Roll-Up이 필요하면 관계를 master-detail로 설계해야 한다.

상세(공유·삭제 동작·junction) → [[Object Relationships]].

## Auto Number (포맷)

- 시스템이 레코드마다 **자동으로 고유 식별자**를 생성. 원문: *"Auto-Number fields automatically generate unique record identifiers using a defined format, such as A-{0000}."*
- 포맷에 접두사 + `{0000}` 자릿수(디스플레이 폭) 지정. 시작 번호 설정 가능.
- **사용자가 편집 불가**(시스템 생성). 레코드 순서가 항상 완벽히 연속임을 보장하진 않는다(공식 KB).

```text
// 구조 예시 — Auto Number 포맷 (실제 org 값 아님)
Display Format : INV-{00000}     → INV-00001, INV-00002 …
Display Format : A-{YYYY}-{0000} → A-2026-0001 …   (날짜 토큰 조합 가능)
Starting Number: 1
```

## Geolocation

- 위도·경도를 **십진수(decimal degrees)** 로 입력하는 복합 필드.
- 범위: **위도 −90 ~ 90**, **경도 −180 ~ 180**.
- 내부적으로 latitude/longitude 두 컴포넌트 + 거리 계산(`DISTANCE`) 용도.

## Encrypted Text (Classic Encryption — 제약 많음)

- 암호화된 텍스트를 저장. **최대 175자.**
- Classic Encryption 기반이며 **제약이 많다**:
  - 기존 필드를 암호화 필드로 **전환 불가**, 암호화 필드를 다른 타입으로 **전환도 불가**(아래 전환 표 참조).
  - Shield Platform Encryption으로 암호화한 필드는 **타입 변경 불가**.
- 규모 있는 암호화가 목적이면 Classic Encrypted Text보다 **Shield Platform Encryption**(표준/커스텀 필드 대상)을 검토.

관련 보안 경계는 [[Field-Level Security (FLS, 필드 수준 보안)]] 참조 — 암호화는 저장 보호, FLS는 접근 통제로 역할이 다르다.

## External Object 전용 — External Lookup vs Indirect Lookup

Salesforce Connect의 **External Object**에서만 쓰는 관계 타입. 일반 커스텀/표준 오브젝트 빌드에선 등장하지 않는다.

| 타입 | 연결 방향 | 매칭 키 |
|---|---|---|
| **External Lookup** | 자식(표준·커스텀·external) → **부모 external object** | 부모 external object의 **표준 External ID 필드** ↔ 자식의 external lookup 값 |
| **Indirect Lookup** | 자식 **external object** → 부모(표준·커스텀) | 부모의 **커스텀 Unique + External ID 필드** ↔ 자식의 indirect lookup 값 |

> 원문(External): *"An external lookup relationship links a child ... object to a parent external object. ... the standard External ID field on the parent external object is matched against the values of the child's external lookup relationship field."*
> 원문(Indirect): *"An indirect lookup relationship links a child external object to a parent standard or custom object. ... Only objects that have a custom field with the External ID and Unique attributes are available as parent objects."*

- **Indirect Lookup 필드는 lookup 검색이 지원되지 않는다** — 값을 편집하려면 부모의 대상 필드값을 직접 입력해야 한다.

## 타입 전환 시 데이터 손실 (Considerations for Converting)

만든 뒤 타입을 바꾸면 **데이터가 사라질 수 있다.** 처음 고를 때 신중해야 하는 이유.

| 상황 | 결과 |
|---|---|
| 암호화 필드 ↔ 다른 타입 | **전환 불가**(양방향). Shield 암호화 필드도 타입 변경 불가 |
| Picklist → Multi-Select | 정의된 값은 유지. **정의에 없는 값을 가진 레코드는 그 값이 삭제됨** |
| 데이터 손실 발생 시 | 그 필드를 쓰던 **리스트 뷰가 삭제**되고, **assignment·escalation rule**이 영향받음 |
| 전환 소요 | 경우에 따라 **24시간 이상** 걸릴 수 있음 |
| 일부 타입 | 애초에 데이터 타입 변경 옵션이 **제공되지 않음** |

> 원문: *"An existing custom field can't be converted into an encrypted field nor can an encrypted field be converted into another data type."* · *"In some cases, the conversion can take over 24 hours to complete."*

> [!warning] 인덱싱·Unique·External ID
> Text·Number·Email·Auto Number 등 일부 타입만 **External ID / Unique** 지정이 가능하고, 이 지정이 **인덱스**를 만든다(업서트 키·빠른 필터). 통합 키로 쓸 필드는 처음부터 이 속성을 지원하는 타입으로 만든다. 커스텀 설정·External Object는 **사용 가능한 데이터 타입이 일부로 제한**된다.

## 빠른 결정 요약

```text
// 구조 예시 — 선택 결정 트리 (실제 원본 다이어그램 아님)
짧은 한 줄 + 필터/키 필요?           → Text (External ID/Unique로 인덱싱)
긴 본문, 필터 불필요?                → Long Text Area (서식 필요하면 Rich Text)
값 목록 중 하나?                     → Picklist   (여럿? → Multi-Select은 신중 / 정석은 관계)
예/아니오?                          → Checkbox
금액?                              → Currency (멀티통화면 CurrencyIsoCode 연동)
이 레코드 값으로 계산?               → Formula
자식들 합·개수?                     → Roll-Up Summary (관계가 master-detail이어야)
두 오브젝트 연결?                    → 느슨=Lookup / 종속·롤업=Master-Detail
자동 채번?                          → Auto Number
좌표?                              → Geolocation
```
