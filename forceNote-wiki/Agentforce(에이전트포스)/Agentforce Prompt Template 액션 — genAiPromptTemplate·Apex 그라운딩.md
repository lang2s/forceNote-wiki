# Agentforce Prompt Template 액션 — genAiPromptTemplate·Apex 그라운딩

> Prompt Template을 에이전트 액션(`generatePromptResponse://<Template>`)으로 호출하고, `GenAiPromptTemplate` 메타로 저작한 플렉스 템플릿을 Apex `@InvocableMethod` 데이터 프로바이더로 그라운딩해 개인화 응답을 생성하는 3층 패턴.

---

## 1. 전체 그림 — 3개 레이어

Prompt Template을 에이전트에서 쓰는 구조는 세 조각이 맞물린다.

```
// 구조 예시 — 실제 원본 다이어그램 아님
Agent Script 액션                 GenAiPromptTemplate 메타              Apex 데이터 프로바이더
target: generatePromptResponse://  ──▶  content(머지필드)          ──▶  @InvocableMethod
  Generate_Personalized_Schedule        {!$Apex:Class.Prompt}            List<Request> → List<Response>
inputs: "Input:email"          ──▶  inputs.referenceName=Input:email     Response.Prompt (grounded JSON)
outputs: promptResponse        ◀──  templateDataProviders(apex://)  ◀──  실제 CRM/SOQL 데이터
```

- **레이어 A (에이전트):** 액션이 `generatePromptResponse://<DeveloperName>` 타깃으로 템플릿을 실행하고, 입력을 `Input:<apiName>`로 전달, 결과를 표준 출력 `promptResponse`(string)로 받는다.
- **레이어 B (템플릿):** `GenAiPromptTemplate` 메타의 `content`에 지시문 + 머지필드가 들어가고, `inputs`가 액션 입력과 이름으로 매칭되며, `templateDataProviders`가 Apex/Flow 프로바이더를 연결한다.
- **레이어 C (그라운딩):** Apex `@InvocableMethod`가 입력을 받아 CRM/Data Cloud/외부 데이터를 조회하고 `Response.Prompt` 문자열로 되돌려, 템플릿 본문의 `{!$Apex:Class.Prompt}` 위치에 삽입된다.

---

## 2. 레이어 A — Agent Script 액션으로 템플릿 실행

### 액션 타깃 URI

| 구성 | 값 | 규칙 |
|---|---|---|
| `target` | `generatePromptResponse://<PromptTemplateDeveloperName>` | 템플릿을 developerName으로 지목. 다른 액션 타깃(`apex://`, `flow://`)과 같은 URI 스킴 패턴 |
| 입력 이름 | `"Input:<apiName>"` | 템플릿 `inputs.referenceName`과 **정확히** 일치해야 바인딩됨 (예 `Input:email`) |
| 출력 이름 | `promptResponse` (string) | Prompt Template 액션의 **표준 단일 출력** — 항상 이 이름의 문자열 하나 |

### 실전 예시 — 액션 정의 (로컬 소스 발췌)

`aiAuthoringBundles/PromptTemplateActions/PromptTemplateActions.agent`:

```agentscript
actions:
    generate_personalized_schedule:
      description: "Generate a personalized schedule with a prompt template. ... This action requires the user's email address."
      inputs:
      # Prompt Template inputs follow pattern, "Input:<Field API Name>"
        "Input:email": string
          description: "User's email address"
          is_required: True

      # Prompt Template output is always a promptResponse string
      outputs:
        promptResponse: string
          description: "The prompt response generated by the action based on the specified prompt and input."
          is_used_by_planner: True
          is_displayable: True
      target: "generatePromptResponse://Generate_Personalized_Schedule"
```

- `is_displayable: True` + `is_used_by_planner: True` → 플래너가 생성 결과를 **중간 변수 저장 없이** 사용자에게 바로 표시한다. 스케줄 텍스트처럼 곧바로 보여줄 콘텐츠에 적합.
- 서브에이전트 인스트럭션에서 `run {!@actions.generate_personalized_schedule}` 형태로 호출하고, 미충족 입력(email)은 다시 물어보게 강제한다.

### 입력 바인딩 (reasoning 액션)

```agentscript
actions:
    generate_personalized_schedule: @actions.generate_personalized_schedule
        with "Input:email" = ...    # 대화에서 수집한 email을 템플릿 입력으로 바인딩
```

> ⚠️ 이름 일치가 핵심: `Input:email`(액션) ↔ `<referenceName>Input:email</referenceName>`(템플릿 메타) ↔ `Request.email`(Apex). 셋 중 하나라도 어긋나면 값이 흐르지 않는다.

## 3. 레이어 B — GenAiPromptTemplate 메타데이터 저작

`generatePromptResponse://`가 실행하는 대상이 이 메타다. **API 60.0+**, Prompt Builder 활성화 + Prompt Template Manager 권한 필요. 파일 접미사 `.genAiPromptTemplate`, 폴더 `genAiPromptTemplates/`.

### GenAiPromptTemplate (루트) 필드

| 필드 | 타입 | 설명 |
|---|---|---|
| `masterLabel` | string | **필수.** 사용자 표시 이름 |
| `developerName` | string | API 이름 — 액션 타깃/머지필드가 이 이름으로 참조 |
| `type` | string | **필수.** 템플릿 종류 (아래 표) |
| `visibility` | enum | `API` 또는 `Global` — 노출 범위 |
| `templateVersions` | GenAiPromptTemplateVersion[] | **필수.** 버전 배열 |
| `activeVersionIdentifier` | string | 활성 버전 식별자 (해시). 63.0에서 `activeVersion`(int) 대체 |
| `description` | string | 템플릿 설명 |
| `relatedEntity` / `relatedField` | string | 연결된 레코드 타입/필드 (record-page형 템플릿) |

### `type` 유효값 (템플릿 종류)

| type 값 | 용도 |
|---|---|
| `einstein_gpt__flex` | **플렉스** — 자유형. 입력·데이터 프로바이더를 자유 구성. **에이전트 액션에 주로 사용** (예시가 이 타입) |
| `einstein_gpt__salesEmail` | Sales 이메일 초안 |
| `einstein_gpt__recordSummary` | 레코드 요약 |
| `einstein_gpt__fieldCompletion` | 필드 자동완성 |
| `einstein_gpt__caseEmailDraft` | 케이스 이메일 초안 |

### GenAiPromptTemplateVersion (버전) 필드

| 필드 | 타입 | 설명 |
|---|---|---|
| `content` | string | **필수.** 프롬프트 본문 — 지시문 + 머지필드 |
| `status` | enum | **필수.** `Published` 또는 `Draft` |
| `inputs` | GenAiPromptTemplateInput[] | 입력 파라미터 배열 |
| `templateDataProviders` | GenAiPromptTemplateDataProvider[] | 데이터 프로바이더(Apex/Flow) 배열 |
| `primaryModel` | string | 연결 모델 (예 `sfdc_ai__DefaultOpenAIGPT4OmniMini`) |
| `generationTemplateConfigs` | GenAiPromptTemplateGenerationConfig[] | 정책(policy) 참조 |
| `versionIdentifier` | string | 자동 생성 버전 식별자 |
| `versionNumber` | int | 순번(1부터). 63.0에서 deprecated |

### GenAiPromptTemplateInput (입력) 필드

| 필드 | 타입 | 설명 |
|---|---|---|
| `apiName` | string | **필수.** 입력 파라미터명 |
| `referenceName` | string | **필수.** 표현식 이름 — `Input:<apiName>` 형식 (액션 입력과 매칭) |
| `definition` | string | **필수.** URI 타입 정의 — `primitive://String`, `SOBJECT://Account` 등 |
| `required` | boolean | **필수.** 필수 여부 |
| `masterLabel` / `description` | string | 표시 이름 / 설명 |

### GenAiPromptTemplateDataProvider + Param (그라운딩 연결)

| 필드 | 타입 | 설명 |
|---|---|---|
| DataProvider `definition` | string | **필수.** `apex://<ClassName>` 또는 `flow://<FlowName>` |
| DataProvider `referenceName` | string | **필수.** 본문에서 참조할 표현식 이름 (예 `Apex:PersonalizedGuestExperiences`) |
| Param `parameterName` | string | **필수.** 프로바이더에 넘길 파라미터명 |
| Param `definition` | string | **필수.** 파라미터 타입 URI |
| Param `valueExpression` | string | 값/표현식 — 보통 입력을 전달 (예 `{!$Input:email}`) |
| Param `isRequired` | boolean | **필수.** 필수 여부 |

### 실전 예시 — 템플릿 메타 (로컬 소스 발췌)

`genAiPromptTemplates/Generate_Personalized_Schedule.genAiPromptTemplate-meta.xml` (핵심 부분):

```xml
<GenAiPromptTemplate xmlns="http://soap.sforce.com/2006/04/metadata">
    <developerName>Generate_Personalized_Schedule</developerName>
    <masterLabel>Generate Personalized Schedule</masterLabel>
    <type>einstein_gpt__flex</type>
    <visibility>Global</visibility>
    <templateVersions>
        <content>Your name is {!$User.FirstName}. You work in the guest success team at {!$Organization.Name}.
... present the list of resort activities happening today that match the guest's interests ...
List of activities happening today that match the guest's interests: {!$Apex:PersonalizedGuestExperiences.Prompt}
</content>
        <inputs>
            <apiName>email</apiName>
            <definition>primitive://String</definition>
            <referenceName>Input:email</referenceName>
            <required>true</required>
        </inputs>
        <primaryModel>sfdc_ai__DefaultOpenAIGPT4OmniMini</primaryModel>
        <status>Published</status>
        <templateDataProviders>
            <definition>apex://PersonalizedGuestExperiences</definition>
            <parameters>
                <definition>primitive://String</definition>
                <isRequired>true</isRequired>
                <parameterName>email</parameterName>
                <valueExpression>{!$Input:email}</valueExpression>
            </parameters>
            <referenceName>Apex:PersonalizedGuestExperiences</referenceName>
        </templateDataProviders>
    </templateVersions>
</GenAiPromptTemplate>
```

### content 머지필드 문법

| 머지필드 | 참조 대상 |
|---|---|
| `{!$Input:email}` | 템플릿 입력 값 |
| `{!$User.FirstName}` | 실행 사용자 컨텍스트 |
| `{!$Organization.Name}` | 조직 컨텍스트 |
| `{!$Apex:<ClassName>.<Prop>}` | Apex 데이터 프로바이더가 반환한 `Response`의 프로퍼티 (예 `.Prompt`) |
| `{!$Flow:<FlowName>.<Out>}` | Flow 데이터 프로바이더 출력 |

> 그라운딩 삽입 위치는 `referenceName`(`Apex:PersonalizedGuestExperiences`) + 프로퍼티명(`Prompt`)으로 결정된다. 즉 `{!$Apex:PersonalizedGuestExperiences.Prompt}`가 SOQL로 조회한 실제 활동 JSON으로 치환된다.

## 4. 레이어 C — Apex 데이터 프로바이더로 그라운딩

그라운딩(grounding) = LLM에 실제 CRM 데이터를 주입해 환각을 줄이고 개인화하는 것. Apex 프로바이더는 Flow보다 유연 — CRM·Data Cloud·외부 데이터 어디서든 조회 가능.

### Apex 계약 (contract)

| 요소 | 규칙 |
|---|---|
| 메서드 | `@InvocableMethod` 표시, `public static List<Response> m(List<Request> requests)` 시그니처 |
| `Request` 이너 클래스 | 템플릿 `inputs`마다 `@InvocableVariable` 멤버 1개. 이름이 입력과 일치해야 함 |
| `Response` 이너 클래스 | `@InvocableVariable public String Prompt;` — 이 문자열이 그라운딩 데이터로 템플릿에 삽입됨 |
| 반환 | `List<Response>` (요소 1개), `res.Prompt`에 직렬화한 데이터 |

### 실전 예시 — 데이터 프로바이더 (로컬 소스 발췌)

`classes/PersonalizedGuestExperiences.cls`:

```apex
public with sharing class PersonalizedGuestExperiences {
    // Make this method available for grounding the Generate_Personalized_Schedule prompt template
    @InvocableMethod(
        label='Get sessions of interest for today'
        description='Get today\'s sessions that match the user\'s interests.'
    )
    public static List<Response> getSessions(List<Request> requests) {
        String email = requests[0].email;

        Id contactId = [
            SELECT Id FROM Contact WHERE Email = :email WITH USER_MODE LIMIT 1
        ].Id;

        List<ASR_Experience__c> experiences =
            ExperienceController.getExperiences(contactId);

        List<Response> responses = new List<Response>();
        Response res = new Response();
        res.prompt = JSON.serialize(experiences);   // 그라운딩 데이터를 문자열로
        responses.add(res);
        return responses;
    }

    // 이 클래스의 변수는 프롬프트 템플릿 입력과 이름이 맞아야 함
    public class Request {
        @InvocableVariable(required=true description='The guest\'s email address')
        public String email;
    }

    public class Response {
        @InvocableVariable
        public String Prompt;   // 템플릿의 {!$Apex:...Prompt} 로 삽입
    }
}
```

- `WITH USER_MODE`로 실행 사용자 권한(FLS/공유)을 존중 — 그라운딩 SOQL의 보안 모범.
- `JSON.serialize()`로 sObject 리스트를 문자열화해 LLM이 파싱하기 쉬운 형태로 전달.

### 두 가지 Apex 그라운딩 연결 방식

Apex를 템플릿에 붙이는 방식이 두 가지 있다 — 예시는 **A**를 쓴다.

| 방식 | 연결 지점 | 특징 |
|---|---|---|
| **A. templateDataProviders (메타 선언형)** | `GenAiPromptTemplate` 메타의 `<templateDataProviders><definition>apex://Class</definition>` + `{!$Apex:Class.Prop}` 머지필드 | 예시 방식. 메타에 프로바이더를 선언하고 본문 머지필드로 삽입. `@InvocableMethod`에 별도 capabilityType 불필요 |
| **B. CapabilityType 라벨형** | `@InvocableMethod(capabilityType='FlexTemplate://<Template_API_Name>')` | Apex 클래스가 자기를 특정 템플릿 capability에 바인딩. Prompt Builder UI 그라운딩 슬롯에 노출 |

> 두 방식 모두 `Request`(입력 매칭)/`Response.Prompt`(반환) 계약은 동일하다.

## 5. 이름 매칭 체크리스트 (가장 흔한 실패 지점)

세 레이어에서 이름이 사슬로 이어져야 한다. 하나라도 어긋나면 값이 흐르지 않는다.

```
// 구조 예시 — 실제 원본 다이어그램 아님
액션 inputs "Input:email"
        │  (문자열 정확히 일치)
템플릿 inputs.referenceName  <referenceName>Input:email</referenceName>
        │  (valueExpression {!$Input:email} 로 프로바이더에 전달)
프로바이더 param parameterName  email
        │  (Request 멤버명 일치)
Apex   Request.email → SOQL → Response.Prompt
        │  (referenceName + 프로퍼티명)
템플릿 content  {!$Apex:PersonalizedGuestExperiences.Prompt}
        │  (표준 출력)
액션 outputs  promptResponse (string)
```
