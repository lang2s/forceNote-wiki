# 컴포넌트 번들 구조와 첫 컴포넌트 만들기

> LWC 컴포넌트는 폴더명과 같은 이름의 파일들로 이뤄진 "번들"이다. 이 노트는 번들의 필수·선택 파일, camelCase 폴더 → `c-kebab-case` 마크업 명명 규칙, 그리고 SFDX CLI로 첫 컴포넌트를 만들어 노출·배포·페이지 배치까지의 절차를 다룬다. `.js-meta.xml`의 개별 필드는 [[XML Config File Elements (js-meta.xml) 레퍼런스]]로 위임한다.

---

## 컴포넌트 번들 = 폴더 하나

LWC 프레임워크가 컴포넌트를 올바른 파일들과 **autowire**(자동 연결)하려면, 모든 파일을 **컴포넌트 이름과 같은 이름의 폴더**에 두고 파일도 같은 이름을 쓴다.

```
// 구조 예시 — 실제 원본 다이어그램 아님
force-app/main/default/lwc/
└── myComponent/
    ├── myComponent.html          (필수*) 마크업 템플릿
    ├── myComponent.js            (필수)  컴포넌트 클래스 로직
    ├── myComponent.js-meta.xml   (필수)  설정 메타데이터
    ├── myComponent.css           (선택)  스타일시트 (폴더당 1개)
    ├── myComponent.svg           (선택)  Setup 팔레트용 아이콘
    ├── myUtils.js                (선택)  공유용 추가 JavaScript
    └── __tests__/                (선택)  Jest 단위 테스트
```

> `*` **HTML 파일은 API 모듈(UI를 렌더하지 않는 서비스 컴포넌트)에는 필수가 아니다.** UI를 렌더하는 일반 컴포넌트는 HTML·JS·설정 3파일이 모두 필요하다.

### 필수 파일 (UI 렌더 컴포넌트 기준)

| 파일 | 역할 |
|---|---|
| `componentName.html` | 컴포넌트 마크업. 최상위 `<template>` 태그로 감싼다. |
| `componentName.js` | `LightningElement`를 확장하는 컴포넌트 클래스. `export default`로 내보낸다. |
| `componentName.js-meta.xml` | 컴포넌트 설정(메타데이터). API 버전·노출 여부·배치 가능한 타깃 등. |

### 선택 파일

| 파일 | 역할 |
|---|---|
| `componentName.css` | 스타일시트. **폴더당 1개**만 암묵적으로 연관된다. |
| `componentName.svg` | Setup의 Lightning App Builder 팔레트에 표시할 커스텀 아이콘. |
| 추가 `*.js` | 다른 파일로 분리한 재사용 코드. import 해서 공유한다. |
| `__tests__/` | Jest 단위 테스트. |

## 명명 규칙 — camelCase 폴더 → `c-kebab-case` 마크업

- 컴포넌트 폴더는 **camel case**로 짓는다: `myComponent`.
- **camel case 폴더명은 마크업에서 kebab-case로 매핑된다.** 예: 폴더 `widget` → `<c-widget>`, 폴더 `myComponent` → `<c-my-component>`.
- 브라우저 콘솔에서 `myComponent`는 `<c-my-component>`로 렌더된다. 여기서 `c`가 **기본 네임스페이스**다.

### 왜 이런 변환이 필요한가

- HTML 표준은 **커스텀 요소 이름에 하이픈(`-`)을 요구**한다.
- 하지만 **Salesforce 플랫폼은 컴포넌트 폴더·파일명에 하이픈을 허용하지 않는다.**
- 모든 LWC는 폴더명과 **하이픈으로 구분되는 네임스페이스**(`c-`)를 갖는다 → 하이픈 없는 폴더명을 쓰면서도 마크업(`c-my-component`)은 HTML 표준을 만족한다.

### 폴더·파일 이름 규칙

이름(name)은 반드시:
- 소문자로 시작한다.
- 영숫자 또는 언더스코어(`_`) 문자만 포함한다.
- 공백을 포함할 수 없다.
- 언더스코어로 끝날 수 없다.
- 연속된 언더스코어 두 개(`__`)를 포함할 수 없다.
- 하이픈(대시)을 포함할 수 없다.

## 첫 컴포넌트 만들기 — 절차

컴포넌트는 SFDX CLI, VS Code 확장, 또는 코드 에디터로 만들 수 있다.

### 1) 생성 — SFDX CLI

Salesforce DX 프로젝트의 `lwc` 디렉터리에 컴포넌트를 스캐폴딩한다.

```bash
# --name 으로 컴포넌트명, --output-dir 로 lwc 디렉터리 지정
sf lightning generate component --type lwc --name myLightningWebComponent --output-dir force-app/main/default/lwc
```

- 생성되는 파일: `myLightningWebComponent.html`, `myLightningWebComponent.js`, `myLightningWebComponent.js-meta.xml` (+ Jest 테스트).
- 생성된 파일은 프로젝트 패키지 디렉터리 안의 `lwc` 디렉터리에 위치한다.

> VS Code 대안: `Cmd/Ctrl + Shift + P` → `sfdx` 입력 → **SFDX: Create Lightning Web Component** 선택. Developer Console에서도 New > Lightning Web Component로 만들 수 있다.

### 2) 마크업·로직 작성

```html
<!-- 구조 예시 — 실제 동작 코드 아님 -->
<!-- myLightningWebComponent.html -->
<template>
    <p>Hello, {greeting}!</p>
</template>
```

```js
// 구조 예시 — 실제 동작 코드 아님
// myLightningWebComponent.js
import { LightningElement } from 'lwc';

export default class MyLightningWebComponent extends LightningElement {
    greeting = 'World';
}
```

### 3) 노출 — `.js-meta.xml`의 `isExposed`·`targets`

컴포넌트를 Lightning App Builder/Experience Builder 등에서 쓰려면 설정 파일에서 노출을 켠다.

```xml
<!-- 구조 예시 — 실제 동작 설정 아님 -->
<!-- myLightningWebComponent.js-meta.xml -->
<?xml version="1.0" encoding="UTF-8"?>
<LightningComponentBundle xmlns="http://soap.sforce.com/2006/04/metadata">
    <apiVersion>62.0</apiVersion>
    <isExposed>true</isExposed>
    <targets>
        <target>lightning__AppPage</target>
        <target>lightning__RecordPage</target>
        <target>lightning__HomePage</target>
    </targets>
</LightningComponentBundle>
```

- `isExposed`가 `false`(기본)면 다른 컴포넌트·App Builder에서 참조할 수 없다.
- `targets`에 나열한 페이지 타입에만 컴포넌트를 드래그해 배치할 수 있다.
- 각 `<target>` 값(29종)·`<targetConfig>`·`<capability>` 등 필드 전수는 → [[XML Config File Elements (js-meta.xml) 레퍼런스]].

### 4) 배포

```bash
# 전체 소스 배포
sf project deploy start --source-dir force-app

# 특정 번들만 배포
sf project deploy start --metadata LightningComponentBundle:myLightningWebComponent
```

### 5) 페이지에 배치

배포 후 Setup에서:
1. Lightning App Builder를 연다 (App Page / Record Page / Home Page 편집).
2. 좌측 컴포넌트 팔레트의 **Custom** 섹션에서 컴포넌트(`c-` 커스텀 컴포넌트)를 찾는다.
3. 캔버스로 드래그해 배치하고 Save·Activate 한다.

> 팔레트에 안 보이면 대부분 `isExposed=false`이거나 해당 페이지 타입이 `targets`에 없다.

## 비교 — 생성 방법 선택

| 방법 | 언제 |
|---|---|
| SFDX CLI (`sf lightning generate component`) | 소스 기반 개발(DX 프로젝트·버전관리·CI). 팀 표준. |
| VS Code 확장 (SFDX: Create Lightning Web Component) | CLI와 동일하나 IDE UI로 편하게. |
| Developer Console | 간단한 실험·빠른 편집. 대규모 개발엔 비권장. |
