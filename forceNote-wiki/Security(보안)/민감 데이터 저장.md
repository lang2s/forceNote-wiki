# 민감 데이터 저장

> password·encryption key·OAuth token·신용카드·PII 같은 sensitive data를 안전하게 저장하기 위한 위협과 Apex/Visualforce 보호 메커니즘.

---

## Sensitive Data 정의 (전수)

- Passwords / Passphrases / Encryption keys / OAuth tokens
- Purchase instruments(신용카드 번호)
- Personal contact info(이름, 전화, 이메일, account username, 물리 주소 등)
- Demographic info(income, gender, age, ethnicity, education)
- 일부 주·국가에서 machine identifying info(MAC address, serial number, IP address)

= **PII** 또는 **HBI(Highly Business Impactful) data**. PCI 같은 compliance 표준을 주의한다.

---

## 위협 항목 (전수)

- **Hardcoded Secrets** — source code에 저장 금지(clear text 노출).
- **Debug Logs** — `system.debug()` 표준 로그/custom 로그에 sensitive data 금지. 이메일·error reporting으로 third party에 전송 금지.
- **Sensitive Info in URL** — username/password/API token/long-lasting access token을 GET query string으로 전송 금지. CSRF token 같은 short-lived는 OK. session ID/PII를 외부 앱에 URL로 전송 금지.
- **Salesforce Integrations** — 외부 DB에 user credential(username/password/session ID) 사용 금지. OAuth flow를 사용.

### Sample Vulnerability

salesforce.com 발 데이터 저장 시 주의한다. plaintext/약한 hash(MD5)로 password를 저장하면 widespread 악용이 발생한다.

---

## How Do I Protect My Application? (암호화 이론 전수)

원문의 점진적 추론 흐름:

1. plaintext 회피 → **encrypt**. 단 "where is the key?" 문제가 남는다.
2. **cryptographic hash(one-way):** `storedPasswordHash = hash(password)` (MD5/SHA1/Tiger/SHA512). 그러나 dictionary precompute 공격에 취약.
3. **salt 추가** → 2^saltSize의 계산을 강제(예: 2-byte salt면 2^16). 그러나 여전히 brute-force 가능(MD5/SHA-1은 1라운드라 부족).
4. **tunably slow hash:** Provos·Mazières의 modified Blowfish(**bcrypt**). 단일 검증은 essentially no time(0.5초도 OK).

salt 적용 의사코드(원문):

```text
// 구조 예시 — 실제 동작 코드 아님 (원문 의사코드 인용)
salt = generateRandomBytes(2)
storedPasswordHash = salt + hash(salt + password)
```

## Apex/Visualforce 보호 메커니즘 (전수)

| 메커니즘 | 설명 |
|---|---|
| **Protected Custom Metadata Types** | namespaced managed package 내에서 사용. 인증 데이터·secret 저장에 적합. type 생성자가 Metadata API로 업데이트 가능. 같은 namespace의 Apex class에서 SOQL로 read(update 불가). 모든 사용자 공통 secret(API key 등)은 Managed Protected Custom Metadata Types에 저장. 코드 hardcode·사용자 노출 금지. |
| **Protected Custom Settings** | `visibility="Protected"` + managed package → Apex code로만 접근. admin 초기화/install time 생성 secret에 유용. **runtime에 Apex class에서 업데이트 가능**, Metadata API로는 불가. VF page에서 `transient` keyword로 view state 전송 방지. limited profile만 접근. |
| **Apex Crypto Functions** | Crypto class가 digest, MAC, signature, AES encryption 제공. AES key는 random 생성 + protected custom setting/metadata type에 안전 저장. Apex class에 hardcode 금지. |
| **Encrypted Custom Fields** | 128-bit key, AES algorithm으로 암호화된 text field. "View Encrypted Data" 권한자만 가시. **인증 데이터 저장은 비권장**, 신용카드·SSN 등 다른 sensitive data에 적합. |
| **Named Credentials** | 외부 서비스 호출(Apex)용 인증 데이터(token) 안전 저장. 신용카드 등은 비권장. customized app 권한자가 named credential 조회 가능. subscriber로부터 secret을 숨겨야 하면 protected custom metadata/setting 사용. |

> Apex Crypto 함수·Encrypted Custom Fields의 암호화 메커니즘 상세(AES 모드, Shield Platform Encryption 등)는 [[Platform Encryption]] 참조. 여기서는 민감 데이터 저장 관점의 선택 가이드만 다룬다.

## General Guidance (전수)

- disk 저장 시 모든 인증 secret(password/API Token/OAuth Token)을 암호화.
- vendor key store 사용(macOS/iOS keychain, Android keystore, Windows DP-API registry).
- 무인 부팅 서버는 DB process가 접근 못 하는 key로 암호화.
- crypto key를 app code에 저장 금지.
- salt + hash, salt·hash를 분리 저장.
- strong platform crypto 사용. framework 기제공 여부 확인.
- SSL/TLS로 전송.

## 플랫폼별 가이드 (전수)

- **ASP.NET** — Windows CryptoAPI, DPAPI. machine key 암호화. 최선은 cryptographic smartcard/HSM + CSP.
- **Java** — `KeyStore` class(기본 flat file + password 암호화 → 대안 CSP 권장). 최선은 HSM/smartcard + vendor CSP(`java.security`). client app은 JAVA binding으로 passphrase를 vendor key store에. source/property file에 passphrase 저장 금지. bcrypt = jBCrypt.
- **PHP** — `/dev/urandom`. PHP 7.x+ `random_int()`(cryptographically secure). mcrypt library. phpass(OpenBSD-style Blowfish bcrypt).
- **Ruby on Rails** — bcrypt-ruby.
- **Python** — python keyring module.
- **Flash/Air** — Encrypted Local Store.
