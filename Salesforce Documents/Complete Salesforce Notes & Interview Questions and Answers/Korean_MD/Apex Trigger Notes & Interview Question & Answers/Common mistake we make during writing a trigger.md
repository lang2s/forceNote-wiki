# 트리거 작성 시 흔한 실수

1. **트리거 미벌크화:** 대량 작업 미처리로 거버너 한도 도달. → 항상 대량 작업 처리 가능하게.
2. **루프 안 SOQL/DML:** 리소스 빠르게 소비. → 쿼리·DML을 루프 밖으로 벌크화.
3. **불완전한 오류 처리:** 예측 불가 동작. → 견고한 오류 처리로 로깅·관리자 알림.
4. **거버너 한도 미고려:** 성능 문제. → 한도를 이해·존중하고 그 안에서 설계.
5. **트리거 컨텍스트 변수 무시:** Trigger.new·old 등 미활용. → 컨텍스트 변수로 관련 레코드 접근.
6. **ID·값 하드코딩:** 유연성 저하·오류. → 상수·Custom Settings 사용.
7. **지나치게 복잡한 로직:** 유지보수 어려움. → 모듈식·문서화·이해하기 쉽게.
8. **향후 재귀 미고려:** 무한 루프. → static 변수·컨텍스트 플래그로 재귀 제어.
9. **단위 테스트 누락:** 미테스트 코드. → 긍정·부정·벌크 시나리오 테스트.
10. **트리거 프레임워크 패턴 미사용:** 관리 불가 코드. → handler·프레임워크 패턴 사용.
11. **검증·워크플로우 규칙에 User ID 하드코딩:** 유지보수 문제. → Hierarchy Custom Settings 등 사용.
12. **비동기 처리 미고려:** 동기·비동기 실행. → 실행 순서 이해, 비동기 시나리오 처리.
13. **벌크 트리거 모범 사례 무시:** 성능 문제. → Map으로 벌크 로직 최적화.
14. **트리거 로직 미문서화:** 다른 개발자가 이해하기 어려움. → 충분한 주석·문서화.
