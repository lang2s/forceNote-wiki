# Master-Detail vs Lookup 관계 선택 고려사항

| 항목 | Master-Detail 관계 | Lookup 관계 |
|---|---|---|
| 표준 오브젝트 제약 | 표준 오브젝트는 관계의 detail/자식 쪽에 둘 수 없음 | 표준/커스텀 오브젝트에서 다른 표준/커스텀 오브젝트로 lookup 필드 생성 가능 |
| 부모 레코드 지정 필수? | 자식 레코드에 부모 레코드 지정 필수 | 부모 레코드 지정을 필수로 할지 선택 가능 |
| 자식 레코드 공유/가시성 | 부모 레코드의 가시성에 의해 결정. 자식의 공유·가시성을 직접 제어 불가 | 자식 레코드의 공유 설정을 부모와 별도로 설정 가능 |
| 부모 삭제 시 영향 | 부모 삭제 시 연결된 자식 레코드도 자동 삭제 | 자식 동작을 제어 가능: 자동 삭제, 자식이 있으면 부모 삭제 제한, 또는 자식의 부모 값 비우기 |
| Roll-up Summary | 부모 오브젝트에 롤업 요약 필드 생성 가능(자식 값 집계·표시) | 자식 값을 자동 집계하는 내장 기능 없음 |
| 거버너 한도 | 자식 오브젝트는 최대 2개의 Master-Detail 관계 | 자식 오브젝트는 최대 40개(자료에 따라 50개)의 lookup 관계 |
