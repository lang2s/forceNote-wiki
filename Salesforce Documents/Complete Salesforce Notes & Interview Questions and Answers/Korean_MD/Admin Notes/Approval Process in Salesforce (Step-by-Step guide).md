# Salesforce 승인 프로세스(Approval Process) — 단계별 가이드

## 승인 프로세스란?

Salesforce의 승인 프로세스는 Opportunity, Lead, Case, 커스텀 오브젝트 같은 레코드에 대한 승인을 자동화하는 방법입니다. 관리자에게 수동으로 승인을 요청하는 대신 Salesforce가 대신 처리합니다.

예: 영업 담당자가 $50,000 규모의 Opportunity를 승인 요청하면, 시스템이 자동으로 영업 관리자에게 라우팅하여 승인 또는 거부할 수 있게 합니다.

## 승인 프로세스 생성 단계

### 1. 승인 프로세스 설정으로 이동

Setup → Quick Find에 "Approval Processes" 입력 → 프로세스를 만들 오브젝트 선택(예: Opportunity, 커스텀 오브젝트) → Create New Approval Process 클릭.

생성 방법 두 가지:
- **Jump Start Wizard:** 기본 설정으로 빠르게 생성
- **Standard Wizard:** 더 많은 커스터마이징(복잡한 승인에 권장)

### 2. 승인 프로세스 세부 정보 정의

- **Process Name:** 명확한 이름 지정(예: "Opportunity Approval")
- **Unique Name:** 자동 생성되며 변경 가능
- **Entry Criteria:** 레코드가 승인 대상이 되는 조건 설정

예시 진입 기준: Opportunity Amount > 10,000(1만 달러 초과만 승인 필요), Stage = Proposal(제안 단계일 때만).

### 3. 승인자 지정

승인자를 누구로 할지 결정합니다:
- **정적 지정(Static):** 특정 인물(예: 영업 관리자)
- **동적 지정(Dynamic):** 레코드의 필드(예: 레코드 소유자의 관리자)
- **Queue 지정:** 사용자 그룹(예: 재무팀, HR팀)

예: 영업 담당자가 Opportunity를 제출하면 "Manager" 필드에 설정된 관리자가 자동으로 승인자가 됩니다.

### 4. 승인 단계(Approval Steps) 정의

Add New Step 클릭 → 조건 설정(예: "금액 > $50K이면 영업 부사장에게 전송") → 승인자 선택(User, Queue, Manager) → 승인 중 레코드 잠금 여부 결정.

예: 1단계(금액 > 10K → 영업 관리자), 2단계(금액 > 50K → 영업 부사장), 3단계(금액 > 100K → CEO).

### 5. 승인 및 거부 액션 구성

- **승인 액션:** 필드 업데이트(예: "Approval Status"를 Approved로), 이메일 전송, 작업 생성.
- **거부 액션:** 필드 업데이트(Rejected로), 피드백과 함께 이메일 알림.

### 6. 최종 승인 및 거부 액션 정의

- **최종 승인 액션:** 마지막 승인 후 발생할 일(예: Opportunity Stage를 "Closed-Won"으로 변경).
- **최종 거부 액션:** 완전 거부 시(예: 거부 이메일 전송, 상태를 "Closed-Lost"로).

### 7. 활성화 및 테스트

Activate 클릭(활성화 후에는 수정 불가). 테스트 레코드를 만들어 제출하며 프로세스 테스트.

## 모범 사례

- **동적 승인자 사용:** 특정 인물 대신 Manager 필드를 사용해 유연성 확보
- **필드 업데이트 설정:** 승인/거부 시 상태 자동 업데이트
- **이메일 템플릿 사용:** 명확한 소통을 위한 알림 커스터마이징
- **샌드박스에서 먼저 테스트:** 운영 배포 전 항상 테스트
