# Salesforce의 데이터 보안과 데이터 접근 수준

데이터 보안은 조직 전반의 사용자 간 데이터 공유 설정과 가시성을 다룹니다. 네 가지 수준: 1) 조직 수준, 2) 오브젝트 수준, 3) 필드 수준, 4) 레코드 수준.

## 1.1 사용자 관리

User는 Salesforce에 로그인하는 모든 사람입니다. 모든 사용자는 사용자 계정을 가지며, 다음을 포함합니다:
- **USERNAME:** 모든 Salesforce 조직에서 고유해야 함.
- **User License:** 사용자가 접근할 수 있는 기능 결정. 회사 필요에 따라 구매.
- **Profile:** 사용자가 무엇을 할 수 있는지 결정. 직무에 따라 선택.
- **Role:** 역할 계층상 위치에 따른 추가 접근 결정. 선택 사항, 사용자당 1개.

**사용자 레코드를 삭제할 수 있나요?** 아니요. 사용자 삭제는 고아(orphaned) 레코드와 중요 비즈니스 정보 손실을 초래할 수 있어 불가능합니다.

### Deactivate vs Freeze

| Deactivate(비활성화) | Freeze(동결) |
|---|---|
| 사용자를 삭제할 수 없으므로 로그인을 막으려면 비활성화 | 비활성화 절차를 수행하는 동안 즉시 막으려면 먼저 동결. Freeze 버튼 클릭 |
| 비활성화는 할당된 라이선스를 해제하여 새 사용자가 사용 가능 | 동결은 라이선스를 해제하지 않음 |

## 1.2 비밀번호 정책 관리 (프로필·조직 수준 모두 설정 가능)

- **Password Policies:** 최소 길이, 복잡성, 만료 기간 등 설정.
- **User Password Resets:** 특정 사용자 비밀번호 재설정.
- **User Password Expiration:** "Password Never Expires" 권한 사용자를 제외하고 일정 기간 후 만료.
- **Login Attempts & Lockout:** 시도 횟수 지정, 잠긴 사용자 잠금 해제.

## 1.3 IP 주소로 로그인 접근 제한

기본적으로 위치를 제한하지 않지만, 보안을 위해 IP로 제한 가능:
- **조직 수준:** 설정된 IP 범위 밖에서 로그인 시 로그인 챌린지(인증 코드 입력) 후 접근 허용. 완전 차단은 아님. 이 IP 범위를 "trusted" IP 범위라 함.
- **프로필 수준:** 허용된 IP 범위 밖 사용자는 항상 접근 거부.

**조직 수준과 프로필 수준 중 어느 것이 더 제한적인가?** 프로필 수준.

## 1.4 시간으로 로그인 접근 제한

프로필 수준에서만 가능(조직 수준은 관리자도 제한할 수 있으므로). 각 프로필에 대해 로그인 가능 시간 지정. 로그인 중 시간이 끝나면 현재 페이지는 볼 수 있지만 추가 작업 불가.

**HEALTH CHECK:** 조직의 보안 설정이 Salesforce 권장 설정과 얼마나 일치하는지 0~100 척도로 보여주는 대시보드.

## 2. 오브젝트 수준 보안

### 2.1 프로필

플랫폼에서 사용자가 접근할 수 있는 데이터·기능을 결정하는 설정·권한의 모음. 템플릿과 같아, 새 프로필을 만들 때 기존 Salesforce 제공 프로필을 선택해 커스터마이징. 한 프로필이 여러 사용자를 가질 수 있음(1-many).

프로필이 제어하는 것: 필드 권한, 사용자 권한, 탭 설정, 앱 설정, Apex 클래스 접근, Visualforce 페이지 접근, 페이지 레이아웃, 레코드 타입, 로그인 시간, 로그인 IP 범위.

### 2.2 권한 집합

기존 프로필 권한 위에 추가 접근을 부여하는 설정·권한 모음. 프로필 수정이나 새 프로필 생성 없이 특정 사용자에게 추가 접근. 만료 날짜(1일·7일·30일·60일·커스텀) 설정 가능. 조직당 최대 1,000개.

**Profile vs Permission Set vs Permission Set Group:**
- 프로필: 가장 제한적 설정, 사용자당 1개 필수.
- 권한 집합: 접근 추가(additive), 사용자당 여러 개.
- 권한 집합 그룹: 여러 권한 집합 묶음. 그룹 내 일부 권한 음소거(mute) 가능(해당 그룹에만 반영). 라이선스는 생성 시 필수는 아니나 한 번 할당하면 변경 불가.

## 3. 필드 수준 보안

사용자가 오브젝트 레코드의 특정 필드 값을 보고 편집할 수 있는지 제어(페이지 레이아웃은 상세·편집 페이지 가시성만 제어). 관련 목록, List View, 리포트, 검색 결과 등 앱 전반에서 필드 가시성 보호.
- **3.1 프로필로 필드 접근 제한:** Read Access, Edit Access 제공.
- **3.2 권한 집합으로 필드 접근 추가:** Read Access, Edit Access 제공. Setup의 Field Accessibility에서도 설정 가능.

## 4. 레코드 수준 보안 (4단계)

### 4.1 OWD
특정 오브젝트에 대한 조직 전체 기준 접근 설정. 가장 제한적으로 설정해야 함. 수준: Public Read/Write(모두 보기·편집), Private(레코드 소유자와 적절한 공유 권한 사용자로 제한). OWD가 Public Read/Write이면 다른 레코드 수준 보안 단계는 의미 없음.

### 4.2 Role Hierarchy
조직 내 사용자 간 보고 관계 표현. "Grant Access by Hierarchy"가 활성화되면 상위(예: Managing Director)가 하위 사용자가 만든 모든 레코드를 볼 수 있음. 원치 않으면 공유 설정에서 체크 해제.

### 4.3 Sharing Rules (소유자 기반/기준 기반)
레코드가 특정 기준에 해당할 때 공유 규칙으로 공유. OWD와 역할 계층이 제공한 접근을 제한할 수는 없음. Public Group, Role, Roles & Subordinates에 공유 가능. 공유 규칙으로 받은 레코드는 해당 사용자가 삭제할 수 없음. Public Group은 역할·프로필과 무관하게 사용자를 그룹화하여 공유 규칙에 사용.

### 4.4 Manual Sharing
기준에 해당하지 않거나 단일 레코드를 공유하려면 사용. 레코드 상세 페이지의 Sharing 버튼 클릭. 레코드에 전체 접근이 있는 사람(시스템 관리자, 레코드 소유자, 역할 계층상 상위, 전체 접근 부여받은 사람)이 공유 가능. 최소한 해당 오브젝트 보기 접근이 있는 누구와도 공유 가능.

## 빠른 복습

1. 한 조직에 관리자가 2명 이상일 수 있나요? 예.
2. 관리자를 강력하게 만드는 두 설정은? View All, Modify All.
3. 사용자가 특정 레코드 타입에 접근 권한이 없으면 그 레코드 타입의 레코드를 볼 수 있나요? 예. 레코드 타입은 UI상 가시성만 제어하고 접근은 제어하지 않음.
4. OWD의 Public Read/Write/Transfer는 어디에만 적용되나요? Lead/Case 오브젝트(소유자가 Lead·Case를 다른 사람에게 이전 가능).
