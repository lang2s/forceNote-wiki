# Salesforce 아키텍처: 멀티테넌트 & 메타데이터 기반

Salesforce는 여러 조직을 효율적으로 서비스하도록 설계된 확장성 높고 안전한 아키텍처의 클라우드 기반 CRM입니다. 두 가지 핵심 원칙: 1) 멀티테넌트 아키텍처, 2) 메타데이터 기반 모델.

## 1. 멀티테넌트 아키텍처

**멀티테넌시란?** 여러 조직(테넌트)이 서버·데이터베이스·리소스를 포함한 동일한 Salesforce 인프라를 공유합니다. 단, 각 테넌트의 데이터는 완전히 격리되고 안전합니다.

예: 여러 비즈니스(테넌트)가 별도 아파트에 살지만 같은 인프라(전기·물·보안)를 공유하는 아파트 건물과 같습니다.

**주요 특징:** 공유 인프라(모든 고객이 같은 하드웨어·소프트웨어 사용), 데이터 격리(각 조직 데이터 분리·보안), 자동 업그레이드(커스터마이징 방해 없이 새 기능 배포), 효율적 리소스 활용(서버 효율 극대화, 비용 절감).

**이점:** 낮은 비용(개별 인프라 불필요), 더 나은 성능(고가용성·속도 최적화), 확장성(여러 조직의 수천 사용자 처리), 보안·규정 준수(엄격한 데이터 분리로 프라이버시 보장).

## 2. 메타데이터 기반 아키텍처

**메타데이터란?** 데이터에 대한 데이터로, 오브젝트·필드·페이지 레이아웃·워크플로우·리포트 등 Salesforce 플랫폼의 구조를 정의합니다.

예: 데이터베이스 테이블을 하드코딩하는 대신, Salesforce는 구성을 메타데이터로 저장하여 핵심 기능에 영향을 주지 않고 쉽게 커스터마이징할 수 있게 합니다.

**작동 방식:** 오브젝트·필드(DB 스크립트 없이 데이터 모델 정의), 페이지 레이아웃·UI 구성(드래그 앤 드롭), 자동화(Workflow·Process Builder·Flow), 리포트·대시보드(메타데이터 기반 동적 시각화).

**이점:** 노코드 커스터마이징, 빠른 개발(선언적 도구), 매끄러운 업그레이드(메타데이터가 커스터마이징 보호), 유연성·적응성(비즈니스 프로세스 쉽게 수정).

## 모범 사례

- 메타데이터 활용(코드 작성 전 Flow·Process Builder 같은 선언적 도구 사용)
- 멀티테넌시 최적화(하드코딩 회피, 거버너 한도 효율적 사용)
- 데이터 적절히 보호(역할·프로필·공유 설정으로 접근 제어)
- API 모범 사례 사용(통합 시 효율적 API 사용)
- 성능 모니터링(리포트·자동화·쿼리 정기 점검)
