# Salesforce Apex 코드 모범 사례 10가지

> (원본은 이미지 PDF로 OCR 추출했습니다.)

1. **Apex 코드 벌크화(Bulkify):** 한 번에 여러 레코드를 처리하는 확장 가능한 코드를 작성하고 거버너 한도를 피합니다.

2. **For 루프 안에서 SOQL & DML 회피:** SOQL이나 DML(insert/update/delete/undelete)을 루프 안에 두지 마세요. 루프 안에 두면 반복마다 데이터베이스 작업이 호출되어 거버너 한도에 쉽게 도달합니다.

3. **대용량 데이터 쿼리:** SOQL은 50,000개 레코드를 반환할 수 있습니다. heap 크기 한도를 초과하는 대용량 데이터 작업 시 SOQL query for 루프를 사용합니다.

4. **SObject의 Map 사용:** 반복 중인 sObject 레코드를 기반으로 다른 sObject의 값을 가져와야 할 때, Map of SObjects를 사용해 루프 안 SOQL을 피합니다.

5. **Limits 클래스 사용:** Apex Limits 메서드를 사용해 거버너 한도 도달을 피합니다(Too many SOQL queries: 101, DML rows 10001, too many query rows 50001 등).

6. **ID 하드코딩하지 않기:** ID는 같지 않을 수 있으므로 코드에 ID를 하드코딩하지 마세요.

7. **데이터베이스 트랜잭션 사용:** 트랜잭션의 모든 작업이 성공적으로 완료되어야 커밋되고, 오류 발생 시 전체 롤백됩니다. Savepoint를 설정해 그 시점의 DB 상태를 지정할 수 있습니다.

8. **비동기 Apex 사용:** 비동기 메서드 내 Apex는 자체적인 더 높은 거버너 한도를 가집니다(예: SOQL 쿼리 100→200, heap 크기·CPU 시간도 증가).

9. **Apex의 예외 처리:** DML 문은 데이터베이스 오류 시 런타임 예외를 반환합니다. try-catch 블록으로 예외를 처리하세요.

10. **오브젝트당 트리거 하나:** Apex 트리거로 작업을 자동화할 때, 오브젝트당 하나의 트리거만 작성하는 것이 모범 사례입니다.
