# 일반 Apex 모범 사례

**Bulkification:** 거버너 한도를 피하기 위해 대량 작업을 효율적으로 처리하도록 설계. 루프 안 쿼리·DML 최소화(루프 안 SOQL·DML 회피).

**오류 처리:** 의미 있는 오류 메시지를 위한 적절한 예외 처리. try-catch 블록으로 우아하게 관리.

**거버너 한도:** 한도를 인식하고 그 안에 머무르도록 설계. 대용량 데이터에는 비동기 처리(Batch Apex, Queueable) 활용.

**코드 주석:** 복잡한 로직 설명 주석 포함. 명확하고 설명적인 변수·메서드 이름 사용.

## 트리거 모범 사례

- **벌크 트리거 설계:** 단일 트랜잭션에서 여러 레코드 처리하도록 벌크화. 루프 안 SOQL·DML 회피.
- **트리거 컨텍스트 변수:** Trigger.new, Trigger.old 등을 활용해 레코드 접근·조작.

## 클래스·메서드 설계

- **관심사 분리:** 단일 책임 원칙. 각 클래스/메서드는 하나의 책임. 복잡한 로직을 작은 모듈식 메서드로 분해.
- **설명적 메서드 이름:** 목적을 명확히 전달하는 이름. 메서드는 잘 정의된 단일 작업 수행.
- **재사용·모듈성:** 재사용 가능한 유틸리티 클래스·메서드 생성. 유지보수·이해를 쉽게 모듈화.

## SOQL & SOSL

- **선택적 쿼리:** 쿼리 행 한도를 피하도록 선택성 최적화. 선택적 WHERE 절로 효율적 필터링.
- **루프 안 SOQL 회피.**

## 비동기 처리

- **Batch Apex:** 대용량 데이터 처리. 배치 간 상태 유지에 Database.Stateful 고려.
- **Queueable Apex:** 복잡한 장시간 프로세스. Queueable 작업 체이닝으로 순차 실행.

## 보안

- **안전한 코딩:** 항상 필드 수준 보안·오브젝트 수준 권한 존중. with sharing / without sharing을 적절히 사용해 데이터 접근 제어.
- **ID 하드코딩 회피:** 레코드 ID 하드코딩 대신 동적 쿼리·Custom Settings·Custom Label·Custom Metadata 사용.

## 테스트

- **포괄적 테스트:** 긍정·부정 시나리오를 다루는 단위 테스트 작성. 모든 클래스 최소 75% 커버리지 목표.
- **테스트 데이터 격리:** 테스트 메서드 내에서 테스트 데이터 생성. 공유 데이터에 @testSetup 사용.
