# Salesforce 공유 및 보안 모델 (Sharing & Security Model) 면접 질문과 답변

## Salesforce 보안 모델 소개

**Q1. Salesforce 보안 모델이란 무엇이며, 플랫폼을 사용하는 조직에 왜 중요한가요?**

Salesforce 보안 모델은 플랫폼 내에서 데이터 무결성과 기밀성을 보장하는 프레임워크입니다. 프로필, 역할, 권한, 공유 설정 등 다양한 기능을 포함합니다. 조직이 민감한 정보에 대한 접근을 제어하고, 데이터 정확성을 유지하며, 규제 요구사항을 준수하도록 돕기 때문에 중요합니다.

## Salesforce 보안 모델

**Q2. 프로필(Profile)과 권한 집합(Permission Set)을 구분하세요.**

프로필은 오브젝트 및 필드 수준 권한을 포함해 사용자가 애플리케이션 내에서 무엇을 할 수 있는지 정의합니다. 권한 집합은 프로필에 할당된 것을 넘어 추가 권한을 부여합니다. 프로필은 사용자 생성 시 할당되지만, 권한 집합은 사용자의 프로필을 변경하지 않고 나중에 추가하거나 제거할 수 있습니다.

**Q3. Salesforce에서 조직 전체 기본값(OWD)의 목적을 설명하세요.**

OWD는 오브젝트의 레코드에 대한 기준(baseline) 접근 수준을 설정합니다. 역할이나 프로필에 관계없이 모든 사용자가 레코드에 대해 갖는 기본 접근 수준을 정의합니다. OWD는 Salesforce 내 전체 데이터 접근 구조를 형성하는 핵심 요소입니다.

**Q4. 프로필과 역할 간 설정이 충돌할 때 Salesforce는 레코드 접근을 어떻게 처리하나요?**

Salesforce는 가장 제한적인(most restrictive) 접근을 적용하여 충돌을 해결합니다. 사용자가 프로필을 통해 읽기 접근 권한이 있지만 역할을 통해 읽기 접근 권한이 없다면, 접근이 거부됩니다.

**Q5. "View All"과 "Modify All" 권한의 의미는?**

소유권이나 공유 규칙에 관계없이 모든 레코드를 보거나 수정할 수 있게 하는 강력한 설정입니다. 보통 관리자 역할에 예약되며, 광범위한 영향 때문에 신중하게 할당해야 합니다.

## 역할 계층과 공유 규칙

**Q1. 역할 계층(Role Hierarchy)은 레코드 접근에 어떤 영향을 주나요?**

역할 계층은 조직 내 사용자에 대한 논리적 순서를 설정합니다. 상위 수준 사용자는 계층에서 자기 아래에 있는 사용자가 소유한 레코드에 접근할 수 있습니다. 이는 하향식(top-down) 데이터 접근 방식을 촉진하고 관리자가 팀 데이터에 접근할 수 있도록 보장합니다.

**Q2. Salesforce에서 수동 공유(Manual Sharing)는 언제 사용하며, 다른 공유 메커니즘과 어떻게 다른가요?**

수동 공유는 특정 레코드에 대해 즉석(ad-hoc) 공유가 필요할 때 사용합니다. 레코드 소유자가 개별 레코드를 다른 사용자나 그룹과 공유할 수 있게 합니다. 더 넓은 규모로 작동하고 종종 자동화되는 역할 계층이나 공유 규칙과 다릅니다.

**Q3. Apex Sharing의 개념과 필요한 경우를 설명하세요.**

Apex Sharing은 개발자가 Apex 코드로 공유 규칙을 프로그래밍 방식으로 정의할 수 있게 합니다. 표준 구성 옵션으로 충족할 수 없는 복잡한 공유 요구사항이 있을 때 유용합니다. 커스텀 비즈니스 로직을 기반으로 레코드 접근에 대한 세밀한 제어가 필요한 시나리오에서 흔히 사용됩니다.

**Q4. Sharing Set이란 무엇이며, 데이터 가시성을 어떻게 향상시키나요?**

Sharing Set은 기준 기반 공유를 정의하여 역할 계층을 넘어 접근을 확장합니다. 지정된 기준을 충족하는 사용자와 레코드를 공유할 수 있어, 레코드 내 필드를 기반으로 접근을 부여하는 유연한 방법을 제공합니다.

**Q5. 공유 규칙(Sharing Rules)과 기준 기반 공유(Criteria-Based Sharing)는 어떻게 다르며, 언제 하나를 다른 것보다 사용하나요?**

둘 다 레코드 접근을 확장하지만, 공유 규칙은 소유권이나 상위 수준에서 정의된 기준을 기반으로 하고, 기준 기반 공유는 더 세분화되어 특정 필드 기준에 따라 접근을 허용합니다. 공유 규칙은 더 광범위하여 더 넓은 그룹이 접근해야 할 때 사용하고, 기준 기반 공유는 더 정밀함을 제공합니다.

## 레코드 소유권과 레코드 이전

**Q1. Salesforce에서 레코드 소유자 변경의 영향을 설명하세요.**

레코드 소유자 변경은 특히 새 소유자가 다른 역할에 있는 경우 레코드 접근에 영향을 줄 수 있습니다. 새 소유자는 자신의 역할에 대한 공유 규칙과 접근 수준을 상속받으며, 적절한 접근을 유지하려면 수동 공유가 필요할 수 있습니다.

**Q2. "Transfer Record" 기능은 공유 및 보안에 어떻게 영향을 주나요?**

관리자가 레코드 소유권을 한 사용자에서 다른 사용자로 이전할 수 있게 하는 강력한 도구입니다. 다만, 레코드 소유권에 의존하는 공유 규칙, 워크플로우 규칙, 기타 프로세스에 미치는 영향을 고려하는 것이 필수적입니다.

**Q3. 워크플로우 규칙으로 레코드 소유권을 변경할 수 있으며, 어떤 점을 고려해야 하나요?**

네, 워크플로우 규칙으로 변경할 수 있지만 신중하게 해야 합니다. 워크플로우 규칙을 통한 소유권 변경은 다른 자동화 프로세스를 트리거할 수 있으며, 관리자는 데이터 접근 문제를 피하기 위해 새 소유자가 필요한 권한을 갖도록 보장해야 합니다.

**Q4. 소유권 기반 공유와 기준 기반 공유의 차이를 설명하세요.**

소유권 기반 공유는 역할 계층과 레코드 소유권에 의해 결정됩니다. 기준 기반 공유는 소유권에 관계없이 특정 기준에 따라 공유를 허용합니다. 소유권 기반 공유가 더 간단하지만, 기준 기반 공유는 커스텀 시나리오에 더 큰 유연성을 제공합니다.

**Q5. Salesforce에서 소유권 기반 공유를 어떻게 재정의(override)할 수 있으며, 왜 그래야 하나요?**

수동 공유나 Apex 공유를 사용해 재정의할 수 있습니다. 소유권을 변경하지 않고 특정 레코드에 임시 접근을 제공하는 등 예외가 필요한 시나리오에서 필요할 수 있습니다.

## 필드 수준 보안과 데이터 암호화

**Q1. 필드 수준 보안(FLS)이란 무엇이며 왜 중요한가요?**

FLS는 오브젝트의 특정 필드에 대한 접근을 제어합니다. 데이터 프라이버시를 유지하고 사용자가 자신의 역할에 관련된 필드에만 접근하도록 보장하는 데 중요합니다. FLS는 프로필 및 권한 집합과 함께 작동합니다.

**Q2. FLS는 오브젝트 수준 보안과 어떻게 다르며, 언제 하나를 다른 것보다 사용하나요?**

오브젝트 수준 보안은 전체 오브젝트에 대한 접근을 제어하고, FLS는 그 오브젝트 내 특정 필드에 대한 접근을 제어합니다. FLS는 더 세분화되어 레코드 내 민감한 데이터에 대한 접근을 제한하는 데 사용됩니다. 오브젝트 수준 보안은 더 광범위하여 전체 레코드 집합에 대한 접근을 제한합니다.

**Q3. Platform Encryption의 사용과 데이터 보안에 미치는 영향을 설명하세요.**

Platform Encryption은 저장된 민감한 데이터(data at rest)를 암호화하여 보호합니다. 규제 산업이나 엄격한 데이터 프라이버시 요구사항이 있는 조직에 특히 중요합니다. 누군가 기반 데이터베이스에 무단으로 접근하더라도 암호화된 데이터는 읽을 수 없도록 보장합니다.

**Q4. Classic Encryption 대신 Shield Platform Encryption을 사용하는 것이 적절한 경우는?**

표준 및 커스텀 오브젝트를 포함한 다양한 오브젝트에 걸쳐 표준 및 커스텀 필드를 암호화해야 할 때 Shield Platform Encryption이 권장됩니다. Classic Encryption은 제한적인 암호화에 적합합니다.

## 공유 및 가시성 향상

**Q1. "Grant Access Using Hierarchies" 옵션은 레코드 가시성에 어떤 영향을 주며, 언제 활성화하지 않을 수 있나요?**

이 옵션을 활성화하면 레코드 접근이 역할 계층을 따라 위로 확장되어, 사용자가 자기 아래 사용자가 소유한 레코드에 접근할 수 있습니다. 매우 민감한 데이터를 다루는 등 일부 시나리오에서는 접근을 엄격히 제어하고 공유 규칙 같은 다른 메커니즘에 의존하기 위해 이 옵션을 활성화하지 않을 수 있습니다.

**Q2. 깊은 역할 계층을 가진 대규모 조직에서 "Grant Access Using Hierarchies" 사용의 영향을 설명하세요.**

깊은 역할 계층을 가진 대규모 조직에서 이를 활성화하면 레코드 접근이 광범위하게 분배될 수 있습니다. 이는 성능에 영향을 줄 수 있으며, 가시성 필요와 시스템 효율성 간의 균형을 위해 공유 규칙과 기타 메커니즘을 신중히 고려해야 합니다.

**Q3. Public Group과 Queue의 차이는 무엇이며, 레코드 접근에 어떤 영향을 주나요?**

Public Group은 레코드에 대한 공통 접근 수준을 공유하는 사용자 집합입니다. Queue는 처리를 기다리는 레코드의 컨테이너입니다. Public Group은 종종 공유 규칙에 사용되고, Queue는 작업 항목을 집합적으로 관리하는 데 사용됩니다.

**Q4. 복잡한 공유 시나리오에서 Apex Managed Sharing의 역할과 한계를 논하세요.**

Apex Managed Sharing은 개발자가 Apex 코드로 커스텀 공유 로직을 만들 수 있게 합니다. 표준 구성으로 부족한 복잡한 공유 시나리오에서 사용됩니다. 다만, 비활성 사용자가 소유한 레코드를 공유할 수 없다는 한계가 있습니다.

**Q5. 공유 규칙 대신 수동 공유를 언제 사용하며, 그 반대는?**

수동 공유는 특정 레코드의 개별적이고 즉석인 공유에 적합하고, 공유 규칙은 기준에 따라 더 광범위한 레코드 접근을 자동화하는 데 적합합니다. 선택은 구체적인 사용 사례와 공유 필요가 일정한지 동적인지에 따라 달라집니다.

**Q6. Territory Management를 권장하는 시나리오와 데이터 가시성에 미치는 영향은?**

Territory Management는 조직이 영역(territory) 기반의 구조화된 영업 계층을 가진 시나리오에서 유용합니다. Account와 Opportunity를 영역에 자동 할당할 수 있어, 정의된 영역 계층에 따라 데이터 가시성과 접근에 영향을 줍니다.

**Q7. 기준 기반 공유와 소유권 기반 공유를 함께 사용해야 하는 실제 시나리오와 구현 예시를 설명하세요.**

영업팀이 지역별로 나뉘어 있고(소유권 기반 공유), 특정 고가치 Opportunity가 특정 기준에 따라 전문팀과 공유되어야 하는(기준 기반 공유) 시나리오에서는 두 메커니즘의 조합이 필요합니다. 예를 들어, 거래 규모가 특정 임계값을 초과하는 Opportunity는 기준 기반 공유를 트리거해 전문팀에 접근을 부여하고, 소유권 계층은 각 지역 내 일반 접근을 보장합니다.

## 고급 보안 개념

**Q1. Cross-Object Formula Field 보안은 표준 FLS와 어떻게 다르며, 언제 사용하나요?**

Cross-Object Formula Field 보안은 사용자가 관련 필드에 접근 권한이 없더라도 관련 오브젝트의 필드를 참조하는 수식 필드를 만들 수 있게 합니다. 전체 데이터 보안을 손상시키지 않고 관련 데이터를 기반으로 값을 계산할 때 유용합니다.

**Q2. Apex의 CRUD 및 FLS 적용의 목적과 보안 강화 방법을 설명하세요.**

Apex의 CRUD(생성, 읽기, 업데이트, 삭제) 및 FLS 적용은 Apex 코드가 수동 사용자 상호작용과 동일한 보안 제약을 따르도록 보장합니다. 플랫폼이 정의한 데이터 접근 및 수정 제한을 적용하여 보안 취약점을 방지하는 데 도움이 됩니다.

**Q3. 보안 관련 이벤트에 Platform Events를 구현하는 시점과 이유는?**

Platform Events는 실시간 이벤트 기반 아키텍처에 활용될 수 있습니다. 중요한 접근 변경이나 로그인 실패 같은 보안 관련 이벤트에 대해 Platform Events를 구현하면 조직이 즉시 대응할 수 있어 보안 모니터링과 대응 능력이 강화됩니다.

**Q4. External Object Sharing 구현 시 고려사항과 모범 사례를 논하세요.**

External Object Sharing은 플랫폼 외부에 저장된 데이터로 접근을 확장합니다. 모범 사례로는 외부 데이터 소스 권한을 신중히 정의하고, 안전한 인증을 위해 Named Credentials를 활용하며, 외부 오브젝트 접근 시 데이터 볼륨과 성능 영향을 고려하는 것이 있습니다.

**Q5. Salesforce Shield의 Event Monitoring은 전체 보안에 어떻게 기여하며, 어떤 유형의 이벤트를 모니터링할 수 있나요?**

Salesforce Shield의 Event Monitoring은 사용자 활동에 대한 상세한 인사이트를 제공하여 잠재적 보안 위협을 모니터링하고 분석하도록 돕습니다. 로그인 시도, 데이터 내보내기 활동, 민감한 데이터 변경 같은 이벤트를 캡처하여 포괄적인 보안 전략에 기여합니다.

**Q6. Classic에서 Lightning Experience로 마이그레이션하는 시나리오에서, 데이터 보안을 유지하며 원활한 전환을 보장하기 위한 핵심 고려사항과 전략을 설명하세요.**

Classic에서 Lightning Experience로의 마이그레이션은 UI 변경뿐 아니라 데이터 보안에 대한 고려도 수반합니다. 핵심 전략에는 페이지 레이아웃에 미치는 영향 검증, 커스텀 컴포넌트가 보안 설정을 준수하는지 확인, UI와 상호작용하는 커스텀 코드나 프로세스 업데이트가 포함됩니다. 또한 전환 중 보안 관련 문제를 식별하고 해결하기 위해 철저한 테스트와 함께 단계적 롤아웃이 필수적입니다.
