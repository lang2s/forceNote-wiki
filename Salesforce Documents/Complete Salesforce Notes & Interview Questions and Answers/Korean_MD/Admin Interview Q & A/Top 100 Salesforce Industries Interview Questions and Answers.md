# Salesforce Industries 면접 질문과 답변 TOP 100

> [!warning] 제3자 학습노트(면접 Q&A)를 한글로 변환한 **Tier 3** 자료입니다. 공식 소스와 대조되지 않았으니 정확도는 공식 문서로 검증하세요.

**1. Salesforce란?**

비용 효율적인 SaaS(Software-as-a-Service)로 제공되는 가장 효과적인 CRM(고객 관계 관리) 제품입니다.

**2. Salesforce의 커스텀 오브젝트란?**

회사와 관련된 데이터를 저장하는 데이터베이스 테이블입니다.

**3. 커스텀 오브젝트는 사용자가 무엇을 하게 해주나요?**

정의되면, 커스텀 필드 생성, 다른 레코드와의 연관, 이벤트 및 작업 추적, 페이지 레이아웃 구축, 커스텀 탭 생성, 데이터 분석, 대시보드 및 리포트 생성을 할 수 있게 합니다.

**4. Self-Relationship이란?**

같은 오브젝트에 대한 Lookup 관계로, 같은 유형의 오브젝트 간에 관계를 만들 수 있게 합니다.

**5. Object Relationship Overview란?**

관련 목록에서 커스텀 오브젝트 레코드를 표준 오브젝트 레코드에 연결합니다. 관련 고객 Case에서 제품 결함을 추적하는 데 유용합니다.

**6. Salesforce에서 데이터 손실의 원인은?**

데이터 타입 변경, 선택 목록 변환, 필드 타입 변경 등 다양한 이유로 데이터 손실이 발생할 수 있습니다.

**7. SaaS가 Salesforce에 어떻게 도움이 되나요?**

SaaS는 클라이언트가 구독 기반 모델을 선택해 무거운 초기 비용과 투자를 피할 수 있게 합니다. 사용자는 페널티 없이 서비스를 중단할 수 있습니다.

**8. Salesforce는 영업을 어떻게 추적하나요?**

일일 응대 고객 수, 일일 매출량, 영업 관리자의 상세 리포트, 월별/분기별 매출 수치, 재구매 고객 활동 같은 기본 세부 정보를 기록하여 추적합니다.

**9. Salesforce.com이 제공하는 관계 유형은 몇 가지인가요?**

Lookup 관계, Master-Detail 관계, Self-Relationship 등 여러 유형을 제공합니다.

## 신입을 위한 질문

**10. Salesforce는 무엇을 하나요?**

기업이 고객과 더 잘 연결되고, 데이터를 관리하고, 활동을 효율적으로 추적하도록 돕는 CRM 소프트웨어와 클라우드 기반 솔루션을 제공합니다.

**11. Salesforce의 자회사는?**

주요 자회사로 Tableau, Pardot, Heroku, Mulesoft, Demandware Inc, SalesforceIQ 등이 있습니다.

**12. Salesforce의 오브젝트란?**

조직의 정보를 저장하는 데이터베이스 테이블로 사용됩니다. 두 가지 유형: Salesforce가 제공하는 표준 오브젝트, 사용자가 만드는 커스텀 오브젝트.

**13. Salesforce의 App이란?**

로고, 이름, 필요한 탭 세트를 담아 특정 기능을 제공하기 위해 함께 작동하는 컨테이너입니다.

**14. SF에서 어떤 유형의 앱을 만들 수 있나요?**

다양한 비즈니스 시나리오에 맞는 커스텀 앱과, 향상된 UI 및 탐색을 위한 콘솔 앱을 만들 수 있습니다.

**15. 두 사용자가 같은 프로필을 가질 수 있나요? 한 사용자에게 두 프로필을 할당할 수 있나요?**

네, 하나의 프로필은 여러 사용자에게 할당될 수 있습니다. 단, 각 사용자는 하나의 프로필만 할당받습니다.

**16. 거버너 한도란?**

멀티테넌트 아키텍처에서 공정한 리소스 할당을 보장하기 위해 공유 데이터베이스에 저장할 수 있는 데이터 양이나 레코드 수에 대한 제한입니다.

**17. 샌드박스 조직이란? 샌드박스의 유형은?**

운영 환경의 복사본으로 테스트와 개발에 사용됩니다. Developer, Developer Pro, Partial Copy, Full Sandbox, Scratch org 등의 유형이 있습니다.

## Salesforce Apex

**18. Apex란?**

커스텀 비즈니스 로직을 구축하고, 외부 시스템과 통합하고, 프로세스를 자동화하는 데 사용되는 프로그래밍 언어입니다.

**19. Apex를 어떻게 구현하나요?**

Apex 클래스, 트리거, Batch Apex, Visualforce 컨트롤러를 사용해 구현할 수 있습니다.

## Salesforce 관리자

**20. Salesforce CRM이란?**

기업이 고객 정보, 상호작용, 영업 프로세스를 효율적으로 관리하도록 돕는 클라우드 기반 소프트웨어입니다.

**21. Salesforce 관리자의 역할은?**

조직의 요구사항을 충족하고 사용자 생산성을 향상시키기 위해 Salesforce 조직을 구성, 커스터마이징, 관리하는 책임을 집니다.

**22. Salesforce에서 접근을 어떻게 제어하나요?**

프로필, 권한 집합, 공유 설정을 통해 관리되며, 누가 레코드와 데이터를 보고, 편집하고, 삭제할 수 있는지 제어합니다.

## Salesforce 개발자

**23. Salesforce 개발자란?**

Apex, Visualforce 등의 기술을 사용해 Salesforce 플랫폼 내에서 솔루션을 커스터마이징하고 개발하는 책임을 집니다.

**24. Apex 코드를 어떻게 테스트하나요?**

코드가 예상대로 작동하고 거버너 한도를 준수하는지 검증하는 단위 테스트(unit test)를 사용해 테스트할 수 있습니다.

## Salesforce FAQ

**25. Salesforce는 데이터 보안을 어떻게 처리하나요?**

사용자 인증, 오브젝트 수준 보안, 필드 수준 보안, 레코드 수준 보안을 포함한 다층 보안 모델을 구현합니다.

**26. Salesforce 데이터 관리 모범 사례는?**

검증 규칙, Data Loader 도구, 데이터 백업 전략을 사용해 데이터 무결성과 보안을 유지하는 것입니다.

## 면접 팁

**27. 성공적인 Salesforce 면접 팁은?**

회사 조사, 일반적인 질문에 대한 답변 준비, 플랫폼 실무 경험 보여주기, 문제 해결 능력 입증 등이 있습니다.

## 선언적 기능, 감사 리포팅

**28. Salesforce 플랫폼 질문이란?**

데이터 모델링, 리포팅, UI 설계 등 플랫폼의 기능과 역량에 관한 주제를 다룹니다.

**29. 자식 레코드를 어떻게 만드나요?**

Master-Detail이나 Lookup 같은 관계를 사용해 부모 레코드와 연관시켜 만들 수 있습니다.

**30. 커스텀 오브젝트란?**

비즈니스 프로세스에 관련된 특정 데이터를 저장하기 위해 사용자가 만드는 오브젝트입니다.

**31. 커스텀 필드를 어떻게 만드나요?**

오브젝트의 설정 페이지로 가서 필드에 적절한 데이터 타입을 선택해 만들 수 있습니다.

**32. UI 설계 기능은?**

페이지 레이아웃, Record Type, 커스텀 버튼 등으로 사용자 경험을 맞춤화하는 기능을 제공합니다.

**33. 커스텀 라벨을 어떻게 사용하나요?**

여러 언어로 번역할 수 있는 텍스트 값을 정의하여 애플리케이션 전반의 다양한 곳에서 사용할 수 있습니다.

**34. Salesforce의 웹 서비스란?**

외부 애플리케이션이 SOAP, REST 같은 표준 프로토콜을 사용해 Salesforce와 상호작용하고 데이터를 교환할 수 있게 하는 인터페이스입니다.

**35. 특정 사용자 선언(specific user declaration)이란?**

개별 사용자에 대한 고유한 데이터 접근 규칙을 정의하여 서로 다른 권한과 접근 수준을 갖게 합니다.

**36. Dynamic Dashboard를 어떻게 만드나요?**

대시보드를 보는 사용자에 따라 콘텐츠를 조정하는 컴포넌트를 사용해 만듭니다.

**37. 오브젝트 관계를 어떻게 만드나요?**

오브젝트 간에 커스텀 관계 필드를 정의하여 만듭니다.

## 프로그래밍 기능

**38. Apex 프로그래밍 언어란?**

커스텀 비즈니스 로직을 추가하여 Salesforce 기능을 확장하는 강타입 객체 지향 프로그래밍 언어입니다.

**39. Apex 클래스를 어떻게 만드나요?**

Developer Console이나 VS Code용 Salesforce Extensions를 사용해 만들 수 있습니다.

**40. Bucket Field란?**

값의 범위나 조건을 기반으로 레코드를 분류할 수 있게 합니다.

**41. Visualforce 컴포넌트를 어떻게 만드나요?**

커스텀 컴포넌트를 정의하고 조직 내 여러 페이지에서 사용하여 만들 수 있습니다.

**42. Visualforce 페이지란?**

개발자가 Salesforce 애플리케이션용 커스텀 UI를 구축할 수 있게 하는 UI 프레임워크입니다.

**43. 테스트 메서드란?**

Apex 코드를 테스트하고 기능과 정확성을 보장하는 데 사용됩니다.

**44. 오류를 어떻게 처리하나요?**

try-catch 블록을 사용해 Apex 코드 실행 중 발생할 수 있는 예외와 오류를 처리할 수 있습니다.

**45. 다양한 데이터 타입은?**

텍스트, 숫자, 날짜, 선택 목록 등 다양한 유형의 데이터를 저장하는 다양한 데이터 타입을 제공합니다.

**46. 사용자 수준 접근을 위한 공유 규칙을 어떻게 정의하나요?**

공유 규칙에 정의된 기준에 따라 특정 레코드에 대한 접근을 확장할 수 있게 합니다.

**47. Apex 트랜잭션이란?**

하나의 작업 단위로 함께 실행되는 일련의 작업을 나타냅니다.

**48. 레코드에 DML 작업을 어떻게 수행하나요?**

DML(Data Manipulation Language) 작업은 데이터베이스에서 레코드를 삽입, 업데이트, 삭제, 쿼리하는 데 사용됩니다.

## 감사 및 리포팅 기능

**49. Audit Trail을 어떻게 활성화하나요?**

Setup > Security Controls > View Setup Audit Trail로 이동해 활성화할 수 있습니다.

**50. 리포트의 유형은?**

Tabular, Summary, Matrix, Joined 리포트.

**51. 리포트를 어떻게 예약하나요?**

지정된 사용자에게 특정 간격으로 자동 실행 및 전달되도록 예약할 수 있습니다.

**52. Report Snapshot이란?**

특정 시점의 리포트 데이터를 캡처해 향후 참조를 위해 저장하는 기능입니다.

## 데이터 모델링과 데이터 관리

**53. Lookup 관계란?**

두 오브젝트를 함께 연결해 관계를 만들 수 있게 합니다.

**54. Lookup 관계를 어떻게 만드나요?**

한 오브젝트에 관련 오브젝트를 가리키는 lookup 필드를 추가해 만들 수 있습니다.

**55. Master-Detail 관계란?**

자식 레코드의 존재가 master 레코드에 의존하는 특별한 유형의 관계입니다.

**56. Master-Detail 관계를 어떻게 만드나요?**

자식 오브젝트에 master 오브젝트로 연결되는 master-detail 필드를 추가해 만들 수 있습니다.

**57. 외부 오브젝트란?**

데이터를 Salesforce로 복사하지 않고 외부 데이터 소스의 데이터에 연결하고 접근할 수 있게 합니다.

**58. 외부 오브젝트를 어떻게 만드나요?**

External Data Source와 External Objects 설정을 사용해 만들 수 있습니다.

## 로직과 프로세스 자동화

**59. 검증 규칙이란?**

레코드가 저장되기 전에 충족해야 하는 특정 기준을 지정해 데이터 품질을 강제합니다.

**60. 검증 규칙을 어떻게 만드나요?**

오브젝트의 설정 페이지로 가서 검증 기준을 정의해 만들 수 있습니다.

**61. Workflow Rule이란?**

특정 기준이 충족되면 액션을 트리거하는 자동화 프로세스입니다.

**62. Workflow Rule을 어떻게 만드나요?**

Setup > Workflow Rules로 이동해 규칙의 기준과 액션을 정의해 만들 수 있습니다.

**63. Process Builder와 Flow란?**

코드 작성 없이 자동화 프로세스와 시각적 워크플로우를 구축하는 데 사용되는 두 가지 강력한 도구입니다.

**64. Process Builder를 어떻게 사용하나요?**

특정 조건이 충족되면 액션을 트리거하는 자동화 프로세스를 만드는 데 사용할 수 있습니다.

**65. Flow를 어떻게 사용하나요?**

프로세스를 자동화하고 사용자 상호작용을 간소화하는 안내형 시각적 워크플로우를 만드는 데 사용할 수 있습니다.

## 소프트웨어 테스팅

**66. Apex 코드를 어떻게 테스트하나요?**

코드가 예상대로 작동하고 거버너 한도를 준수하는지 검증하는 단위 테스트를 사용합니다.

**67. 단위 테스트란?**

Apex 코드의 동작과 기능을 검증하기 위해 테스트 메서드를 작성하는 것입니다.

**68. 테스트 메서드를 어떻게 만드나요?**

@isTest 어노테이션을 사용하고 다양한 시나리오를 시뮬레이션하는 테스트 코드를 작성해 만들 수 있습니다.

**69. Test Data Factory 메서드란?**

다양한 시나리오를 시뮬레이션하고 Apex 코드 기능을 테스트하기 위해 단위 테스트에서 테스트 데이터를 만드는 데 사용됩니다.

## 디버그 및 배포 도구

**70. Developer Console이란?**

개발자가 Apex 코드를 작성, 실행, 디버그할 수 있는 통합 개발 환경입니다.

**71. Developer Console을 어떻게 사용하나요?**

Salesforce Setup 메뉴에서 접근할 수 있으며, 코드 편집기, 로그, Apex 코드 테스트용 Execute Anonymous 같은 기능을 제공합니다.

**72. Apex Debugger란?**

개발자가 Apex 코드를 한 줄씩 단계별로 실행하고 실행 중 변수를 검사할 수 있는 Developer Console의 도구입니다.

## 통합 기능

**73. Salesforce를 외부 시스템과 어떻게 통합하나요?**

REST API, SOAP API, Apex 콜아웃 같은 다양한 통합 도구를 제공해 외부 시스템과 연결하고 데이터를 교환합니다.

**74. REST API란?**

외부 애플리케이션이 Salesforce와 상호작용하고 Salesforce 레코드에 CRUD 작업을 수행할 수 있게 하는 웹 서비스입니다.

**75. SOAP API란?**

웹 서비스에서 구조화된 정보를 교환하는 데 사용되는 프로토콜로, 외부 시스템과 데이터를 교환할 수 있게 합니다.

**76. REST API를 어떻게 사용하나요?**

GET, POST, PUT, DELETE 같은 HTTP 메서드를 사용해 Salesforce 데이터를 인증하고 상호작용할 수 있습니다.

**77. SOAP API를 어떻게 사용하나요?**

XML 기반 요청/응답 메시지를 사용해 Salesforce 오브젝트에 CRUD 작업을 수행할 수 있습니다.

## 프로그래밍 기능

**78. Apex란?**

커스텀 비즈니스 로직을 구축하고, 외부 시스템과 통합하고, 프로세스를 자동화하는 데 사용되는 프로그래밍 언어입니다.

**79. Apex를 어떻게 구현하나요?**

Apex 클래스, 트리거, Batch Apex, Visualforce 컨트롤러를 사용해 구현할 수 있습니다.

**80. 트리거의 용도는?**

레코드가 삽입, 업데이트, 삭제, 복원되기 전후에 프로세스를 자동화하고 액션을 수행하는 데 사용됩니다.

**81. Batch Apex 클래스란?**

거버너 한도에 도달하지 않도록 대량의 데이터를 비동기적으로 처리하는 데 사용됩니다.

**82. Visualforce 페이지란?**

개발자가 Salesforce 애플리케이션용 커스텀 UI를 구축할 수 있게 하는 UI 프레임워크입니다.

**83. Visualforce 페이지를 어떻게 만드나요?**

마크업을 정의하고 필요한 컴포넌트와 태그를 포함해 만들 수 있습니다.

**84. 트리거란?**

레코드에 특정 DML 이벤트가 발생하기 전후에 실행되는 Apex 코드입니다.

**85. Apex 트리거를 어떻게 작성하나요?**

트리거 컨텍스트를 만들고 트리거할 오브젝트와 이벤트를 지정해 작성할 수 있습니다.

**86. 트리거 컨텍스트란?**

트리거를 발동시킨 레코드와 이벤트를 트리거한 작업 유형에 대한 정보를 제공합니다.

**87. Trigger.old란?**

트리거 이벤트로 업데이트되기 전 레코드의 이전 버전을 저장하는 컬렉션입니다.

**88. Trigger.new란?**

트리거 이벤트로 업데이트된 후 레코드의 새 버전을 저장하는 컬렉션입니다.

**89. Future 메서드란?**

메서드를 비동기적으로 실행하여 다른 작업이 계속되는 동안 백그라운드에서 실행되게 합니다.

**90. Future 메서드를 어떻게 호출하나요?**

메서드 선언 앞에 @future 어노테이션을 사용해 호출할 수 있습니다.

**91. 트리거와 워크플로우의 차이는?**

트리거는 특정 이벤트 발생 시 커스텀 코드를 실행하는 데 사용되고, 워크플로우는 정의된 기준과 액션을 기반으로 프로세스를 자동화하는 데 사용됩니다.

**92. Apex 트리거의 유형은?**

레코드 처리 중 실행 시점에 따라 before 트리거와 after 트리거 두 가지가 있습니다.

## Salesforce 관리자

**93. Salesforce CRM이란?**

기업이 고객 정보, 상호작용, 영업 프로세스를 효율적으로 관리하도록 돕는 클라우드 기반 소프트웨어입니다.

**94. Salesforce 관리자의 역할은?**

조직의 요구사항을 충족하고 사용자 생산성을 향상시키기 위해 Salesforce 조직을 구성, 커스터마이징, 관리합니다.

**95. 접근을 어떻게 제어하나요?**

프로필, 권한 집합, 공유 설정을 통해 누가 레코드와 데이터를 보고, 편집하고, 삭제할 수 있는지 제어합니다.

**96. 커스텀 앱을 어떻게 만드나요?**

Setup 메뉴 > "Build" 섹션의 "Apps"를 선택한 뒤 "New"를 클릭하고, 앱 이름·설명·로고를 선택하고 포함할 탭을 선택해 만듭니다.

**97. 커스텀 오브젝트를 어떻게 만드나요?**

Setup 메뉴 > "Build" 섹션의 "Objects"를 선택한 뒤 "New Custom Object"를 클릭하고 오브젝트의 속성과 필드를 정의해 만듭니다.

**98. 샌드박스 조직이란? 샌드박스의 유형은?**

운영 환경의 복사본으로 테스트와 개발에 사용됩니다. Developer, Developer Pro, Partial Copy, Full Sandbox, Scratch org 등의 유형이 있습니다.

**99. 필드 수준 보안을 어떻게 활성화하나요?**

오브젝트의 설정 페이지로 가서 서로 다른 프로필과 권한 집합에 대해 접근을 제어할 필드를 선택해 활성화할 수 있습니다.

**100. Salesforce의 사용자 라이선스 유형은?**

Salesforce, Salesforce Platform, Salesforce Platform One 등 다양한 유형의 사용자 라이선스를 제공하며, 각각 서로 다른 접근 수준과 기능을 가집니다.
