# 비동기 Apex 노트

> [!warning] 제3자 학습노트(면접 Q&A)를 한글로 변환한 **Tier 3** 자료입니다. 공식 소스와 대조되지 않았으니 정확도는 공식 문서로 검증하세요.

백그라운드에서 실행되는 Apex 코드로, 작업 완료를 기다리지 않고 프로세스가 계속되게 함. 리소스 집약적·시간 소요·즉시 결과 불필요한 작업에 적합.

**사용 이유:** 거버너 한도 회피, 대량 데이터 작업 성능 향상, 복잡한 비즈니스 로직 처리.

## 비동기 Apex 유형

1. **Future 메서드** — 단순한 논블로킹 작업. 즉시 반환. 트랜잭션당 50개 제한.
2. **Queueable Apex** — Future보다 유연. 작업 체이닝 가능(완료 후 다른 작업 호출). 다단계 복잡 작업에 적합.
3. **Batch Apex** — 대량 데이터를 작은 청크로 처리. stateful 작업으로 대규모 비동기 실행. 최대 5천만 건.
4. **Scheduled Apex** — 특정 시간·간격 실행. 데이터 정리·리포트 등 반복 작업.

## Future 메서드
백그라운드에서 비동기 실행, UI 미차단.
**사용 사례:** 이메일 알림, 외부 웹서비스 콜아웃, 사용자 요청 후 장기 실행 로직.

## Queueable Apex
Future보다 제어력이 높아 복잡한 비동기 작업을 큐에서 처리. 체이닝 가능, 순차 처리에 적합, 유연성 높음.

## Batch Apex
대량 데이터를 관리 가능한 청크로 비동기 처리.
**사용 사례:** 데이터 마이그레이션, 대규모 처리(배치 단위 업데이트), 대량 데이터 정리.

## Scheduled Apex
특정 시간·간격(매일·매주)에 실행.
**사용 사례:** 리포트 자동 생성, 정기 유지보수, 오프피크 복잡 프로세스.

## 제한 사항
- **거버너 한도**: Future 호출 수, 배치 크기, 큐 작업 수에 엄격한 한도.
- **오류 처리**: 비즉시성으로 디버깅 어려움.
- **실행 순서**: 보장되지 않음(특히 체이닝 시).

## 사용 시점
- 시간 소요 작업(사용자 경험 영향)
- 대량 데이터(동기 실행 시 거버너 한도 초과)
- UI 미차단 백그라운드 처리

## 모범 사례
- 거버너 한도 항상 고려
- 견고한 오류 처리 구현
- Batch는 적절한 배치 크기 사용
- Queueable 체이닝은 장기 큐 방지를 위해 신중히 사용
