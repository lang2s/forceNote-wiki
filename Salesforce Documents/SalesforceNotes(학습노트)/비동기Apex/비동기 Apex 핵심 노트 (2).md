# 비동기 Apex 핵심 노트

> [!warning] 제3자 학습노트(면접 Q&A)를 한글로 변환한 **Tier 3** 자료입니다. 공식 소스와 대조되지 않았으니 정확도는 공식 문서로 검증하세요.

비동기 Apex는 사용자 경험을 방해하지 않고 백그라운드에서 프로세스를 실행하는 기능. 장기 실행 프로세스, 복잡한 계산, 거버너 한도를 초과할 수 있는 작업에 유용. 온라인 주문 후 배송 시 이메일을 받는 것처럼, 실시간으로 완료를 기다릴 필요가 없다.

## 비동기 vs 동기

| 비동기 | 동기 |
|---|---|
| 트랜잭션/프로세스를 차단하지 않는 작업 | 빠르고 즉각적인 작업 |
| 소요 시간이 우선 아님 | 즉시·직렬 트랜잭션 |
| 더 높은 거버너 한도 | 일반 거버너 한도 |

**동기 프로그래밍:**

작업이 순차적으로 실행, 하나가 끝나야 다음으로. 예: ATM 현금 인출(카드 삽입→PIN→금액→잔액 확인→지급). 각 단계는 순서대로 완료되어야 하며 실시간 응답 필요.

**동기의 단점:**

지연·대기 시간, 리소스 차단, 확장성 병목, 단일 실패 지점(한 단계 실패 시 전체 중단).

## 비동기 Apex를 쓰는 이유
장기 실행·리소스 집약 작업을 백그라운드 처리해 성능·확장성·신뢰성 향상. 대량 데이터셋·장기 프로세스 처리, 대기 시간 없음, 더 높은 거버너 한도.

- **성능**: 백그라운드 처리로 UI 반응성 유지.
- **거버너 한도**: 동기 한도 우회.
- **배치 처리**: 대량 데이터를 관리 가능한 청크로.
- **시간 소요 작업**: 이메일, HTTP 호출, 복잡한 계산에 이상적.
- **작업 체이닝**: 순차 실행 가능.

## 동기 Apex vs 비동기 Apex

| 측면 | 동기 Apex | 비동기 Apex |
|---|---|---|
| 실행 시점 | 즉시·실시간 | 트랜잭션 완료 후 백그라운드 |
| 사용 사례 | 실시간 업데이트·즉시 트랜잭션 | 대규모 처리·백그라운드 작업 |
| 트랜잭션 | 동일 트랜잭션 컨텍스트 | 별도 트랜잭션 |
| 데이터 처리 | 중소 규모 | 대규모·시간 소요 |
| 거버너 한도 | 대량 시 초과 가능성 높음 | 일부 한도 우회 |
| 예 | 클릭 시 레코드 생성·업데이트 | 배치 처리·대량 이메일 |
| 성능 | 무거운 처리 시 UI 느려짐 | UI 영향 없음 |
| 오류 처리 | 전체 트랜잭션 롤백 | 원래 트랜잭션 영향 없음 |
| 데이터 가시성 | 트랜잭션 내 즉시 | 비동기 작업 완료 후 |

> 동기 Apex로 단일 클릭에 15,000건 이상 업데이트 시 거버너 한도 초과(10,000건 한도). 비동기 Apex는 대량 데이터를 작은 배치로 나눠 한도 없이 처리.

## 유형
- **Future 메서드** (@future): 코드 비동기 실행.
- **Batch Apex**: 대량 데이터셋을 배치로 처리.
- **Queueable Apex**: 유연성·체이닝 제공.
- **Scheduled Apex**: 예약된 시간에 실행.
