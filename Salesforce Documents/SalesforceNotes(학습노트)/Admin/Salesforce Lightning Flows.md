# Salesforce Lightning Flows

> [!warning] 제3자 학습노트(면접 Q&A)를 한글로 변환한 **Tier 3** 자료입니다. 공식 소스와 대조되지 않았으니 정확도는 공식 문서로 검증하세요.

## Flow란?

코드 작성 없이 복잡한 비즈니스 프로세스를 구축할 수 있는 강력한 자동화 도구입니다. 반복 작업 자동화, 안내형 워크플로우, 레코드 업데이트, 승인, 외부 시스템 통합을 가능하게 합니다.

## 왜 사용하나요?

- 수작업 감소: 프로세스 자동화로 시간·노력 절약
- 데이터 일관성 향상: 정확하고 일관된 업데이트
- 사용자 경험 개선: 구조화된 프로세스로 안내
- 개발자 의존 최소화: 비즈니스 사용자가 코드 없이 자동화 생성
- 프로세스 효율 증가: 복잡한 로직을 실시간 실행

## 언제 사용하나요?

- 프로세스에 사용자 상호작용이 필요할 때(예: 양식을 통한 Lead 자격 판단)
- 조건에 따라 레코드 업데이트·자동화가 필요할 때
- 레코드 생성·업데이트 시 액션을 자동 트리거할 때
- 예약 자동화가 필요할 때(예: 월간 리포트 전송)
- 이벤트 기반 자동화가 필요할 때

## Flow 유형

**Screen Flow:** 사용자가 시작(버튼·링크), UI에서 실행. 구조화된 UI 비즈니스 프로세스로 안내할 때. 예: 서비스 상담원이 고객 문제 기록 단계 따르기.

**Record-Triggered Flow:** 레코드 생성·업데이트·삭제 시, 백그라운드 실행. 사용자 상호작용 없이 레코드 변경 기반 자동화. 예: 관련 Opportunity 마감 시 Account 상태 자동 업데이트.

**Platform-Triggered Flow:** 플랫폼 이벤트 발행 시, 백그라운드 실행. 실시간 이벤트 기반 아키텍처에 대응. 예: 외부 시스템으로 고우선순위 주문이 들어오면 영업 관리자 알림.

**Scheduled-Triggered Flow:** 특정 시간·빈도(매일·매주) 도달 시, 백그라운드 실행. 예약 간격으로 자동 작업. 예: 매주 월요일 오전 9시 미완료 작업 리마인더 이메일.

**Auto-Launched Flow:** 다른 플로우·Apex·REST API가 호출, 백그라운드 실행. 프로그래밍 방식으로 트리거되는 재사용 가능한 로직. 예: 고객이 설문 완료 후 후속 이메일 자동 전송.

## 모범 사례

- 플로우를 단순·모듈식으로(큰 플로우를 작은 subflow로 분할)
- Decision 요소 효율적 사용(과도한 분기 회피)
- 루프 안 DML 제한(컬렉션으로 대량 처리)
- 철저히 테스트(Debug Mode, 배포 전 샌드박스)
- 적절한 곳에 Flow 사용(매우 복잡한 로직은 Apex 고려)

## 한계

성능·확장성 문제, 디버깅 어려움, 버전 관리 부재, 대량 처리 어려움, 직접적인 오브젝트 간 참조 불가.

## 장점

노코드 자동화, 향상된 사용자 경험, 빠른 구현, Salesforce 기능과 통합, 선언적 디버깅·로깅, 재사용성·모듈성, 비용 효율적.

## 단점

성능·거버너 한도, 디버깅 복잡성, 버전 관리 부재, 제한적 오브젝트 간 참조, 대규모 처리 부적합, 복잡 시나리오 유지보수 어려움, Screen Flow의 UI 제한.

## 결론

중간 수준 자동화와 안내형 프로세스에는 Flow를, 대용량 데이터 처리·복잡한 로직·API 통합에는 Apex를 사용하세요. Flow는 관리자·비즈니스 사용자에게 강력한 자동화를 제공하지만 대용량·복잡 처리·디버깅에는 한계가 있습니다.
