# Salesforce의 리포트(Reports)

> [!warning] 제3자 학습노트(면접 Q&A)를 한글로 변환한 **Tier 3** 자료입니다. 공식 소스와 대조되지 않았으니 정확도는 공식 문서로 검증하세요.

리포트는 데이터를 조직화된 방식으로 보여주는 도구입니다. Salesforce 정보를 살펴보고 분석하여 더 나은 결정을 내릴 수 있게 합니다. 매출 수치, 고객 정보, 열린 지원 Case 등을 명확한 형식으로 표시하는 데이터 스냅샷이라고 생각할 수 있습니다.

**주요 특징:**
1. **커스터마이징 가능:** Account, Opportunity, Case 등 포함할 데이터를 선택하고 필터 적용.
2. **실시간 데이터:** 라이브 데이터 표시로 항상 최신 정보.
3. **대화형:** 세부 정보로 드릴다운하거나 데이터를 그룹화해 패턴 분석.
4. **시각적:** 차트·대시보드와 결합해 이해하기 쉽게.

## 리포트 타입(Report Type)

리포트의 오브젝트 간 구조와 관계를 정의합니다. 어떤 레코드·필드를 포함할 수 있는지 결정하는 청사진 역할을 합니다.

**표준 리포트 타입:**
- 모든 표준·커스텀 오브젝트에 대해 자동 생성.
- 단일 오브젝트 또는 관련 오브젝트의 데이터 포함.
- 예: "Accounts with Contacts" 타입으로 Account 세부 정보와 관련 Contact 정보를 함께 조회.

**커스텀 리포트 타입:**
- 표준 타입에 없는 특정 필드·관계를 포함하도록 생성.
- 최대 4개 오브젝트 관계 정의(Account, Opportunity, Contact, Case).
- 예: "Opportunities"와 "Cases"를 결합해 잠재 거래와 연결된 제품 이슈 분석.

**리포트 타입 카테고리:**
1. Primary Object Only(단일 오브젝트)
2. Primary Object with Related Object(s)(메인+관련)
3. Cross-Object Relationships(공통 필드로 연결된 비관련 오브젝트 간 관계)

**핵심 고려사항:**

필드 가용성은 오브젝트·필드 권한·가시성에 따름. 행 접근은 오브젝트·필드·레코드 수준 보안을 준수.

## 리포트의 목적

매출 성과·고객 이슈·매출 추세 같은 핵심 지표 추적, 의사 결정을 위한 실행 가능한 인사이트 제공, 예약 리포트로 정기 리포팅 자동화.

## 리포트 유형 (예시 포함)

### Tabular Report

가장 단순한 유형으로, 스프레드시트처럼 행과 열의 기본 표 형식으로 데이터 표시. 그룹화나 계산 없이 레코드 목록 작성에 유용.
- 특징: 원시 데이터를 행·열로 표시, 그룹화·요약 불가, 내보내기에 적합, (행 제한 없으면) 대시보드 사용 불가.
- 사용 시점: Contact·Lead 같은 단순 목록 생성, 오프라인 분석을 위한 데이터 내보내기.

### Summary Report

그룹화와 소계로 데이터를 조직화하여 추세 분석·정보 요약에 이상적. 하나 이상의 필드로 그룹화 가능.
- 특징: 행 기준 데이터 그룹화, 각 그룹 소계 자동 계산, 차트 포함 가능, 대시보드 소스로 사용 가능.
- 사용 시점: 지역·제품별 매출 같은 데이터 추세 분석, 카테고리별 합계·소계 제공.
- 예: 영업 담당자별 총 매출 그룹화(John Doe 합계 $15,000, Jane Smith 합계 $30,000).

### Matrix Report

행과 열 모두로 데이터를 그룹화해 복잡한 비교 가능. 가장 고급 유형으로 다차원 분석에 이상적.
- 특징: 행·열 이중 그룹화, 각 그룹 소계와 총계, 차트 지원, 대시보드 사용 가능.
- 사용 시점: 두 카테고리 동시 분석, 지역·제품별 성과 같은 복잡한 리포팅.
- 예: 지역(행)·제품 카테고리(열)별 매출, 총 $300,000.

### Joined Report

여러 리포트 타입의 데이터를 단일 뷰로 결합. 서로 다른 오브젝트·관점의 데이터를 나란히 비교·분석할 때 유용.
- 특징: 최대 5개 블록(섹션), 각 블록은 같거나 다른 리포트 타입 표시, 블록별 독립 필터·정렬·그룹화, 대시보드 호환.
- 사용 시점: 서로 다른 오브젝트의 데이터 비교, 데이터셋 간 관계 조회(예: Account·Opportunity와 관련된 Case).
- 예: Account별 열린 Case(블록1)와 Opportunity(블록2).

## 리포트 보안 작동 방식

리포트 보안은 플랫폼의 기본 데이터 접근 제어에 의해 관리되어, 사용자가 권한이 있는 데이터만 봅니다.

1. **오브젝트 수준 보안:** 오브젝트에 "Read" 접근이 있어야 데이터 포함 가능(프로필·권한 집합 제어).
2. **필드 수준 보안:** 숨겨진 필드는 제한된 사용자의 리포트에 표시되지 않음(예: 급여 필드).
3. **레코드 수준 보안:** OWD, 역할 계층, 공유 규칙, 수동 공유를 통해 접근 가능한 레코드만 표시.
4. **폴더 보안:** 리포트는 가시성 제어가 있는 폴더에 저장(private, 특정 사용자·그룹 공유, public). 폴더 접근이 있어야 리포트 보기·실행 가능.
5. **리포트 타입 보안:** 커스텀 리포트 타입은 포함된 오브젝트 접근을 상속. 오브젝트 접근이 없으면 실행 불가.
6. **행 수준 데이터 필터:** 필터는 보안 설정을 무시하지 않음. 접근 허용된 행만 표시.

**모범 사례:**

공유 설정을 비즈니스 요구에 맞춤, 정기 보안 감사, 민감 데이터에 필드 수준 보안, 커스텀 리포트 타입 활용.

## 결론

Salesforce는 리포트 보안을 플랫폼의 데이터 보안 모델과 긴밀히 통합하여, 사용자가 권한이 있는 데이터만 보도록 보장합니다.
