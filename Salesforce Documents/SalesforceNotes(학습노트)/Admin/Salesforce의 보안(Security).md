# Salesforce의 보안(Security)

> [!warning] 제3자 학습노트(면접 Q&A)를 한글로 변환한 **Tier 3** 자료입니다. 공식 소스와 대조되지 않았으니 정확도는 공식 문서로 검증하세요.

Salesforce 보안은 데이터가 보호되고 적절한 사용자가 적절한 시간에만 접근하도록 보장합니다. 다루는 범위: 1) 누가 접근하는가(로그인 제한, IP), 2) 무엇을 할 수 있는가(보기·편집·삭제), 3) 어떤 데이터를 보는가(레코드·필드), 4) 어떻게 추적·보호되는가(감사 로그, 암호화).

## 보호 계층

1. **로그인 보안:** 비밀번호, MFA, IP 제한으로 승인된 사용자만 접근.
2. **권한:** 허용된 데이터만 보기·편집(오브젝트·필드·레코드 수준 제어).
3. **데이터 암호화:** 민감 데이터를 스크램블해 승인된 사용자만 읽기.
4. **모니터링:** 사용자 작업·변경 추적으로 의심 활동 감지.
5. **백업·복구:** 정기 백업으로 필요 시 복원.

## 보안 유형

**1. 조직 수준 보안:** Salesforce 환경 접근 제어. 로그인 접근(IP 제한, 로그인 시간), 인증(MFA, SSO), 비밀번호 정책(복잡성·만료·이력).

**2. 오브젝트 수준 보안:** 사용자가 어떤 오브젝트를 보기·생성·편집·삭제할 수 있는지 결정. Profiles(그룹 권한), Permission Sets(프로필 변경 없이 추가), Permission Set Groups(묶음), 표준·커스텀 오브젝트에 적용.

**3. 필드 수준 보안:** 오브젝트의 어떤 필드를 보기·편집할 수 있는지 제어. Visible(보기·편집), Read-Only(보기만), Hidden(불가). 사용 예: 주민번호·급여 같은 민감 필드 숨김.

**4. 레코드 수준 보안:** 개별 레코드 접근 제어. OWD(기준 수준), Role Hierarchy(하위 레코드 접근), Sharing Rules(기준 기반 확장), Manual Sharing(개별 공유), Territory Management(영역 기반).

**5. 데이터 암호화:** 저장·전송 중 민감 데이터 보호. Shield Platform Encryption(필드·첨부), TLS(전송 중).

**6. 감사 및 모니터링:** 데이터·구성 변경 추적. Field History Tracking, Audit Trail, Event Monitoring, Login History.

**7. 보안 모범 사례:** Profiles·Permission Sets로 최소 권한, 모든 사용자 MFA, 필드 수준 보안·공유 설정 정기 감사, 민감 데이터에 Shield Encryption, 보안 인식 교육.

## 보안 개념 요약표

| 보안 계층 | 하는 일 | 예시 |
|---|---|---|
| 조직 수준 | 누가 어떻게 로그인하는지 제어 | 근무 시간 중 사무실 네트워크에서만 로그인 |
| 오브젝트 수준 | 데이터 오브젝트로 할 수 있는 작업 정의 | 영업사원은 Accounts 편집 가능, Employee Records 불가 |
| 필드 수준 | 레코드의 특정 필드 접근 제어 | 고객명은 보지만 신용카드 번호는 못 봄 |
| 레코드 수준 | 개별 레코드 접근 제어 | 관리자는 모든 계정, 담당자는 자기 것만 |
| 데이터 암호화 | 민감 데이터를 읽을 수 없게 보호 | 신용카드 번호 스크램블 |
| 감사·모니터링 | 변경·사용자 활동 추적 | 레코드 업데이트·로그인 시마다 기록 |
| 규정 준수 | 법적 규칙·규제 준수 | GDPR 준수 개인정보 마스킹 |

## 실시간 시나리오

Sales, Finance, HR 부서가 있는 고가 장비 판매 회사:
1. **조직 수준:** IP 제한(회사 네트워크), 로그인 시간(오전 9시~오후 6시). 오후 6시 이후 집에서 로그인 시도 → 거부.
2. **오브젝트 수준:** 영업 담당자는 Account 보기·편집, HR은 Account 레코드조차 못 봄.
3. **필드 수준:** 영업 담당자는 고객명·주소·전화는 보지만 신용카드 필드는 숨겨짐(Finance만).
4. **레코드 수준:** Role Hierarchy로 관리자는 팀 계정 모두, 담당자는 자기 것만. Sharing Rules로 관리자는 전체, 담당자는 할당 고객만.
5. **데이터 암호화:** Shield Encryption으로 저장 데이터 암호화. 복호화 키 없이는 의미 없는 문자로 보임.
6. **감사·모니터링:** Login History(누가 언제 어떤 기기로), Field History Tracking(민감 필드 변경 기록).
7. **규정 준수:** Data Masking(테스트 시 마스킹), Retention Policies(일정 기간 후 삭제). 고객 삭제 요청 시 DB에서 삭제.

## 결론

여러 보안 기능이 함께 작동하여 데이터를 보호하고 접근을 제어함으로써, 직원이 업무에 필요한 것만 보고 할 수 있도록 안전한 비즈니스 운영 환경을 제공합니다.
