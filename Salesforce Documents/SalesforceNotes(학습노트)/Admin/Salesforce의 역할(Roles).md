# Salesforce의 역할(Roles)

> [!warning] 제3자 학습노트(면접 Q&A)를 한글로 변환한 **Tier 3** 자료입니다. 공식 소스와 대조되지 않았으니 정확도는 공식 문서로 검증하세요.

## 1. Role이란?

역할 계층 내의 지정으로, 계층상 위치에 따라 사용자가 볼 수 있는 데이터를 결정합니다. 조직 구조를 반영하고 사용자가 자신의 수준에 관련된 데이터에만 접근하도록 보장합니다.

## 2. 역할의 목적

- **레코드 접근 제어:** 사용자가 볼 수 있는 레코드 결정. 계층 상위 사용자는 부하 직원이 소유한 모든 레코드 접근.
- **협업:** 팀이 효율적으로 데이터 공유·관리.
- **리포팅:** 사용자 역할에 따라 리포트·대시보드에 표시되는 데이터 결정.

## 3. 역할 계층(Role Hierarchy)

조직도와 같습니다. 보고와 데이터 가시성 측면에서 사용자 역할이 어떻게 구조화되는지 나타냅니다. 상위 역할은 하위 역할의 데이터 가시성을 상속합니다.

예: CEO(최상위)는 회사의 모든 레코드를, Sales Manager(중간)는 팀 레코드를, Sales Representative(말단)는 자기 레코드만 봅니다.

## 4. 주요 특징

1. **프로필과 다름:** 역할은 레코드 수준 접근 제어, 프로필은 오브젝트 수준 권한(생성·읽기·업데이트·삭제) 제어.
2. **공유 규칙:** 역할은 공유 규칙과 함께 작동해 역할 계층 밖 사용자에게 접근 확장.
3. **Grant Access Using Hierarchies:** 기본적으로 역할 계층으로 레코드 접근 부여. 필요 없는 특정 오브젝트에는 비활성화 가능.

## 5. 역할 생성과 할당

- **설정:** Setup → Roles → 조직 계층에 따라 역할 정의.
- **할당:** 각 사용자는 하나의 역할 할당. 사용자 생성 시 또는 나중에 할당 가능.

## 6. 역할 계층 예시

| 역할 | 접근 수준 |
|---|---|
| CEO | 조직 전체의 모든 레코드 |
| Regional Manager | 자기 지역 내 모든 레코드 |
| Sales Manager | 팀의 레코드 |
| Sales Representative | 자기 레코드만 |

## 7. 역할의 이점

1. 향상된 보안: 민감 데이터를 승인된 인원에게만 표시.
2. 간소화된 리포팅: 역할 기반 관련 데이터 제공.
3. 효율적 협업: 팀 내 원활한 데이터 공유.

## 8. 실무 시나리오

영업 조직에서: 영업 담당자가 거래 정보 입력 → 영업 관리자가 팀이 제출한 거래 검토 → 지역 관리자가 지역 내 모든 거래 감독 → CEO가 전 세계 모든 거래 가시성 확보. 이렇게 역할이 각 수준에서 적절한 데이터 가시성을 보장합니다.

## 9. 구현 팁

- 간단하게 시작: 넓은 역할로 시작해 필요에 따라 다듬기.
- 공유 규칙 신중히 사용: 역할 계층 너머로 접근 확장 시.
- 정기 감사: 조직 변화에 맞게 역할 할당 검토.
