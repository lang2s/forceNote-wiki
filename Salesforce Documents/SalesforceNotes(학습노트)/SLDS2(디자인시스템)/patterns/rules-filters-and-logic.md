# Rules, Filters, and Logic

> 카테고리: SLDS 2 디자인 패턴 · [공식](https://www.lightningdesignsystem.com/2e1ef8501/p/58ff5f-rules-filters-and-logic)

조건·기준·결정 경로로 데이터를 정제하고 결과를 자동화·제어. 논리 표현식을 **읽기 쉽고 다루기 쉽게**.

## 철학: Invisible, Intuitive, Powerful
- 최상의 인터페이스는 논리 요소가 거의 보이지 않을 정도로 직관적. 사용자가 데이터의 형태·내용을 유연하게 사고하도록.
- 흔히 논리 표현식은 **액션을 트리거**(예: 조건 충족 시 맞춤 이메일 발송). 사용자가 시스템 동작을 신뢰하도록 구성은 읽기 쉽게.

## 언제 쓰나
- 값 결정·액션 실행 조건 설정, 코드 없이 복잡한 if/else, 데이터셋 규칙 선택, 사용자 기준 필터링.
- (다중 조건 워크플로/비즈니스 프로세스는 **Builder** 프레임워크 고려)

## 요소 선택 기준 (필요한 것만 노출)
- **사용자가 직접 규칙 추가 가능한가?**
  - 아니오 → 간단한 검색 입력 + facet 표시.
  - 예 → **expression 컴포넌트**로 직접 논리 표현식 추가.
- **논리 모드(모든 조건 충족/임의 조건 충족)를 바꿀 수 있나?**
  - 아니오 → 기본 "모든 조건 충족", 토글 표시 안 함.
  - 예 → expression 컴포넌트로 논리 모드 토글 제공.
- 규칙 추가·모드 변경이 없으면 **combobox·dual listbox·select·text input** 같은 친숙한 요소로 빠른 접근.
- 고급 표현식은 expression 컴포넌트로 복잡도에 맞게 확장. 변형: 로직 모드 2~3개+공식이면 라디오 그룹, 세로 공간 부족 시 collapsible 래퍼에 중첩, 가로 공간 부족 시 panel + narrow expression.
