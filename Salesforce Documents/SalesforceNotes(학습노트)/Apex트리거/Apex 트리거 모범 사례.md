# Apex 트리거 모범 사례

> [!warning] 제3자 학습노트(면접 Q&A)를 한글로 변환한 **Tier 3** 자료입니다. 공식 소스와 대조되지 않았으니 정확도는 공식 문서로 검증하세요.

고품질·효율·확장 가능한 코드를 위해 모든 개발자가 따라야 할 필수 사항입니다.

1. **오브젝트당 트리거 하나:** 트리거 간 충돌 방지, 유지보수성 확보.
2. **명명 규칙 준수:** 트리거 목적과 오브젝트를 쉽게 식별.
3. **필요한 이벤트만 사용:** 불필요한 실행 회피, 성능 개선.
4. **컨텍스트별 핸들러 메서드:** 트리거 컨텍스트(before insert 등)별 핸들러 분리.
5. **로직 없는 트리거:** 트리거에는 컨텍스트 로직만, 비즈니스 로직은 별도 클래스에 위임.
6. **벌크화:** 대량 데이터 처리로 거버너 한도 회피·성능 개선.
7. **컬렉션 사용, FOR 루프 안 SOQL·DML 회피:** List·Set으로 대량 처리.
8. **SOQL Query FOR 루프:** 대용량 데이터 처리로 heap 한도 예외 회피.
9. **Future 메서드 적절히 사용:** 필요할 때만, 한계·성능 고려.
10. **하드코딩 회피:** ID는 환경 간 변경되어 문제 유발.
11. **재귀 트리거 회피:** static Boolean 변수로 실행 추적.
12. **After Undelete 잊지 않기:** 복원 후 관련 레코드 복구에 유용.
13. **트리거 작성 전 Process Builder·Flow 고려:** 단순 로직은 선언적 도구로.
14. **커스텀 트리거 프레임워크 사용:** 모범 사례 강제·유지보수성·테스트 용이.

## 결론

모범 사례를 따르면 트리거가 잘 설계되고 최적화되며 유지보수가 쉬워져, 안정적·신뢰할 수 있는 Salesforce 환경과 우수한 사용자 경험을 제공합니다.
