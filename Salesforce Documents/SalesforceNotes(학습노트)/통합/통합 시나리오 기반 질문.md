> [!warning] 제3자 학습노트(통합 시나리오 Q&A)를 한글로 변환한 **Tier 3** 자료입니다. 답변·코드는 표준 Apex 통합 패턴 기준으로 작성했으나, 구현 전 공식 문서로 검증하세요.

> 형식: **의도** = 평가 포인트, **자주 막히는 부분** = 함정, **A** = 표준 해법(구조 예시).

## Q: 외부 시스템에서 대량 데이터(예: 100만 건)를 Salesforce로 처리·통합. Batch Apex 작성
**의도:**

Batch Apex·대량 데이터·성능 최적화·거버너 한도·오류 처리 이해.

**자주 막히는 부분:**

대량 데이터 최적화(청크 크기·쿼리) 미흡, 콜아웃 한도·타임아웃 미처리, 오류 처리·재시도 로직 부재.

- **A:** `Database.Batchable` + `Database.AllowsCallouts` + `Database.Stateful`(에러 누적). `execute`당 1~2회 콜아웃(콜아웃 100건 한도 ÷ 청크), `Database.insert(list, false)`로 부분 성공, finish에서 실패 집계·재시도.
```apex
// 구조 예시 — 실제 동작 코드 아님
public class ExternalSyncBatch
    implements Database.Batchable<Integer>, Database.AllowsCallouts, Database.Stateful {
    private Integer failures = 0;
    public Iterable<Integer> start(Database.BatchableContext bc) {
        return new PageRange(1, 5000);   // 외부 페이지 번호 목록 (200건/페이지)
    }
    public void execute(Database.BatchableContext bc, List<Integer> pages) {
        List<Account> toUpsert = new List<Account>();
        for (Integer p : pages) {
            HttpResponse res = callExternal(p);          // 페이지당 콜아웃
            if (res.getStatusCode() == 200) toUpsert.addAll(parse(res));
        }
        for (Database.UpsertResult r : Database.upsert(toUpsert, Account.External_Id__c, false)) {
            if (!r.isSuccess()) failures++;              // 부분 실패 수집
        }
    }
    public void finish(Database.BatchableContext bc) {
        // 실패 알림·재시도 잡 enqueue
    }
    private HttpResponse callExternal(Integer page) { return new HttpResponse(); }
    private List<Account> parse(HttpResponse r) { return new List<Account>(); }
    public class PageRange implements Iterable<Integer> {
        Integer a, b; public PageRange(Integer a, Integer b){this.a=a;this.b=b;}
        public Iterator<Integer> iterator(){ return new List<Integer>().iterator(); }
    }
}
// Database.executeBatch(new ExternalSyncBatch(), 1);  // 콜아웃 한도 고려해 작은 scope
```

## Q: Salesforce와 Google API(Drive·Calendar) 통합. Drive에 파일 업로드 코드
**의도:**

OAuth 2.0·파일 업로드·서드파티 API 이해. 토큰 관리·API 할당량.

**자주 막히는 부분:** 토큰 하드코딩·갱신 누락, multipart 업로드 형식 오류, 파일 크기·rate limit·heap 한도 미고려.

- **A:** **Named Credential + External Credential**(Google OAuth 2.0)로 토큰 자동 관리. Drive `files` 엔드포인트에 콜아웃(소형은 단순 업로드, 대형은 resumable). 응답의 `id`/`webViewLink`를 Salesforce에 저장.
```apex
// 구조 예시 — 실제 동작 코드 아님
public static String uploadToDrive(String fileName, Blob content) {
    HttpRequest req = new HttpRequest();
    req.setEndpoint('callout:Google_Drive/upload/drive/v3/files?uploadType=media');
    req.setMethod('POST');
    req.setHeader('Content-Type', 'application/octet-stream');  // 단순 업로드
    req.setBodyAsBlob(content);                                 // heap·콜아웃 6MB 한도 유의
    HttpResponse res = new Http().send(req);
    if (res.getStatusCode() == 200) {
        Map<String, Object> body = (Map<String, Object>) JSON.deserializeUntyped(res.getBody());
        return (String) body.get('id');
    }
    throw new CalloutException('Drive 업로드 실패: ' + res.getStatusCode());
}
```

## Q: 통합 코드 테스트 클래스 작성. REST API 콜아웃 테스트 클래스
**의도:**

단위 테스트·Mock 콜아웃·커버리지 이해.

**자주 막히는 부분:**

HttpCalloutMock 미사용, 100% 커버리지 실패, 의미 있는 assertion 부재.

- **A:** 테스트에서는 실제 콜아웃이 금지되므로 **`HttpCalloutMock`** 구현체를 `Test.setMock`으로 등록. 성공·실패 응답을 각각 시뮬레이션하고 결과를 **assert**.
```apex
// 구조 예시 — 실제 동작 코드 아님
@isTest
private class CalloutServiceTest {
    private class MockOk implements HttpCalloutMock {
        public HttpResponse respond(HttpRequest req) {
            HttpResponse res = new HttpResponse();
            res.setStatusCode(200);
            res.setBody('{"id":"A-100"}');
            return res;
        }
    }
    @isTest static void testSuccess() {
        Test.setMock(HttpCalloutMock.class, new MockOk());
        Test.startTest();
        String id = CalloutService.fetchId();
        Test.stopTest();
        System.assertEquals('A-100', id, '응답에서 id를 파싱해야 함');
    }
}
```
