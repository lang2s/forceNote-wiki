# Salesforce 데이터 보안(Data Security) Q&A 질문

> [!warning] 제3자 학습노트(면접 Q&A)를 한글로 변환한 **Tier 3** 자료입니다. 공식 소스와 대조되지 않았으니 정확도는 공식 문서로 검증하세요.

> (원본은 이미지 PDF였으며 OCR로 텍스트를 추출했습니다.)

Salesforce의 보안은 데이터가 보호되고 적절한 사용자가 적절한 시간에만 접근할 수 있도록 보장합니다. 로그인 제어, 권한, 암호화 같은 기능으로 정보를 안전하게 유지하면서 사용자가 효율적으로 일할 수 있게 합니다. 다루는 범위:

1. 누가 Salesforce에 접근할 수 있는가 (로그인 제한, IP 주소)
2. 사용자가 무엇을 할 수 있는가 (데이터 보기·편집·삭제)
3. 어떤 데이터를 볼 수 있는가 (특정 레코드·필드)
4. 데이터가 어떻게 추적·보호되는가 (감사 로그, 암호화)

## 보호 계층

1. **로그인 보안:** 비밀번호, 다중 인증(MFA), IP 제한으로 승인된 사용자만 접근.
2. **권한:** 사용자가 허용된 데이터만 보거나 편집. 오브젝트(Account), 필드(Salary), 레코드(단일 고객 파일) 수준 제어.
3. **데이터 암호화:** 민감한 데이터를 스크램블해 승인된 사용자만 읽을 수 있게 함.
4. **모니터링:** 사용자 작업과 변경을 추적해 의심스러운 활동 감지.
5. **백업 및 복구:** 정기 백업으로 필요 시 데이터 복원.

## 보안 유형

### 1. 조직 수준 보안(Organization-Level Security)

- **목적:** Salesforce 환경 접근 제어
- **로그인 접근:** IP 제한(특정 IP 범위로 제한), 로그인 시간(허용 시간 정의)
- **인증:** 다중 인증(MFA), Single Sign-On(SSO)
- **비밀번호 정책:** 복잡성, 만료, 이력 규칙 설정

### 2. 오브젝트 수준 보안(Object-Level Security)

- **목적:** 사용자가 어떤 오브젝트를 보기·생성·편집·삭제할 수 있는지 결정
- **기능:** Profiles(그룹별 오브젝트 권한 정의), Permission Sets(프로필 변경 없이 추가 권한), Permission Set Groups(권한 집합 묶음), 표준/커스텀 오브젝트에 적용

### 3. 필드 수준 보안(Field-Level Security)

- **목적:** 오브젝트의 어떤 필드를 보기·편집할 수 있는지 제어
- **기능:** 프로필·권한 집합에서 필드 가시성 설정. 필드 상태: Visible(보기·편집), Read-Only(보기만), Hidden(보기·편집 불가)
- **사례:** 주민번호나 급여 같은 민감 필드를 특정 그룹으로부터 숨김

### 4. 레코드 수준 보안(Record-Level Security)

- **목적:** 오브젝트 내 개별 레코드 접근 제어
- **기능:** OWD(기준 접근 수준 설정), Role Hierarchy(하위 사용자 레코드 접근 부여), Sharing Rules(기준 기반 접근 확장), Manual Sharing(개별 레코드 공유), Territory Management(영역 기반 접근)

### 5. 데이터 암호화(Data Encryption)

- **목적:** 저장 및 전송 중 민감 데이터 보호
- **기능:** Shield Platform Encryption(데이터 필드·첨부 암호화), TLS(전송 중 암호화)

### 6. 감사 및 모니터링(Auditing and Monitoring)

- **목적:** 데이터·구성 변경 추적
- **기능:** Field History Tracking(특정 필드 변경 추적), Audit Trail(조직 수준 설정 변경 로그), Event Monitoring(사용자 활동·성능 추적), Login History(로그인 시도·실패 모니터링)

### 7. 보안 모범 사례

- Profiles와 Permission Sets로 최소 권한(least privilege) 적용
- 모든 사용자에게 MFA 구현
- 필드 수준 보안과 공유 설정 정기 감사
- 민감 데이터에 Shield Platform Encryption 사용
- 사용자에게 보안 인식과 적절한 데이터 처리 교육

## 보안 개념 요약표

| 보안 계층 | 하는 일 | 예시 |
|---|---|---|
| 조직 수준 | 누가 어떻게 로그인하는지 제어 | 근무 시간 중 사무실 네트워크에서만 로그인 허용 |
| 오브젝트 수준 | 사용자가 데이터 오브젝트로 할 수 있는 작업 정의 | 영업 담당자는 Accounts 편집 가능하나 Employee Records는 불가 |
| 필드 수준 | 레코드의 특정 필드 접근 제어 | 영업 담당자는 고객명은 보지만 신용카드 번호는 못 봄 |
| 레코드 수준 | 개별 레코드 접근 제어 | 관리자는 모든 고객 계정, 담당자는 자기 것만 |
| 데이터 암호화 | 민감 데이터를 읽을 수 없게 보호 | 신용카드 번호 스크램블 |
| 감사·모니터링 | 변경과 사용자 활동 추적 | 레코드 업데이트·로그인 시마다 기록 |
| 규정 준수 | 법적 규칙·규제 준수 | GDPR 준수를 위한 개인정보 마스킹 |

## 실시간 시나리오

고가 장비를 판매하는 회사에 Sales, Finance, HR 부서가 있고 각 부서가 서로 다른 데이터에 접근해야 하는 경우:

1. **조직 수준:** IP 제한(회사 네트워크만), 로그인 시간(오전 9시~오후 6시). 직원이 오후 6시 이후 집에서 로그인 시도 → 거부.
2. **오브젝트 수준:** 영업 담당자는 Account 보기·편집 가능, HR은 Account 레코드조차 못 봄.
3. **필드 수준:** 영업 담당자는 고객명·주소·전화는 보지만 신용카드 필드는 숨겨짐(Finance만 가능).
4. **레코드 수준:** Role Hierarchy로 관리자는 팀 계정 모두 접근, 담당자는 자기 것만. Sharing Rules로 관리자는 전체, 담당자는 할당된 고객만.
5. **데이터 암호화:** Shield Encryption으로 저장 데이터 암호화. 복호화 키 없이는 암호화된 데이터가 의미 없는 문자로 보임.
6. **감사·모니터링:** Login History(누가 언제 어떤 기기로), Field History Tracking(민감 필드 변경 기록). 청구 주소 변경 시 관리자가 감사 로그로 변경자 확인.
7. **규정 준수:** Data Masking(테스트 시 마스킹), Retention Policies(일정 기간 후 삭제). 고객이 개인정보 삭제 요청 시 DB에서 삭제.

## 결론

Salesforce의 보안 기능들이 함께 작동하여 데이터를 보호하고 접근을 제어함으로써, 직원이 업무에 필요한 것만 보고 할 수 있도록 보장합니다. 민감 데이터 보호, 가시성 제어, 사용자 활동 추적을 통해 안전한 비즈니스 운영 환경을 제공합니다.
