# 시나리오 기반 Salesforce 배포(Deployment) 질문

> [!warning] 제3자 학습노트(면접 Q&A)를 한글로 변환한 **Tier 3** 자료입니다. 공식 소스와 대조되지 않았으니 정확도는 공식 문서로 검증하세요.

**시나리오: 새로운 Territory Management(영역 관리) 모델을 배포했지만 Account가 올바르게 할당되지 않습니다. 어떻게 해결하나요?**

- Territory 계층(Hierarchy)이 올바르게 설정되었는지 확인합니다.
- 할당 규칙(assignment rules)이 Account 데이터와 일치하는지 검증합니다.
- 사용자가 올바른 Territory 할당을 받았는지 확인합니다.
- 공유 설정(Sharing Settings)을 살펴 적절한 접근 제어를 확인합니다.
- 수동 영역 할당 프로세스를 실행해 테스트합니다.

**시나리오: 영업팀을 위한 새로운 Lightning App을 배포했지만 그들이 앱을 볼 수 없습니다. 무엇이 문제일 수 있나요?**

- 앱이 올바른 프로필에 할당되었는지 확인합니다. 앱의 가시성 설정이 접근을 제한하는지 확인합니다.
- 앱이 Lightning Experience용으로 활성화되었는지 검증합니다.
- App Manager 설정을 살펴 앱이 올바르게 구성되었는지 확인합니다.
- 영업 사용자로 로그인해 앱 목록을 확인하며 테스트합니다.

**시나리오: 할인 승인을 위한 승인 프로세스(Approval Process)를 배포했지만 레코드가 다음 단계로 넘어가지 않습니다. 무엇을 확인하나요?**

- 승인 프로세스가 활성(active) 상태인지 확인합니다.
- 진입 기준(entry criteria)이 제출된 레코드와 일치하는지 검증합니다.
- 지정된 승인자(approver)가 활성 상태이며 로그인 권한이 있는지 확인합니다.
- 영향받은 레코드의 승인 이력(Approval History)에서 오류 메시지를 확인합니다.
- 테스트 Opportunity를 제출하고 진행 상황을 추적하며 테스트합니다.

**시나리오: Account 오브젝트에 검증 규칙(Validation Rule)을 배포했더니 사용자들이 Account를 생성하거나 업데이트할 수 없다고 보고합니다. 무엇을 확인하나요?**

- 검증 규칙 기준이 올바르게 정의되었는지 확인합니다.
- 규칙이 통합(integration)이나 트리거 같은 시스템 프로세스에 영향을 주는지 확인합니다.
- 규칙이 모든 프로필에 적용되는지, 아니면 특정 프로필에만 적용되는지 검증합니다.
- 디버그 로그(Debug Logs)를 살펴 발생하는 오류 메시지를 확인합니다.
- 샘플 데이터로 Account를 생성/업데이트하며 테스트합니다.

**시나리오: 커스텀 Apex REST API를 배포했지만 외부 시스템이 연결하지 못합니다. 어떻게 문제를 해결하나요?**

- Remote Site Settings 또는 Named Credentials가 구성되었는지 확인합니다.
- @RestResource 어노테이션을 사용해 API가 외부 접근용으로 활성화되었는지 확인합니다.
- 통합 사용자(integration user)가 적절한 API 접근 권한을 가지고 있는지 검증합니다.
- 디버그 로그와 API 사용 한도에서 오류를 점검합니다.
- 적절한 인증과 함께 Postman 또는 cURL을 사용해 테스트합니다.

**시나리오: 샌드박스에서 운영 환경으로 100만 개의 레코드를 배포해야 합니다. 어떤 접근 방식을 취하나요?**

- 대용량 데이터를 처리하기 위해 Bulk API 또는 Data Loader를 배치 모드로 사용합니다.
- 거버너 한도에 도달하지 않도록 데이터를 더 작은 배치로 분할합니다.
- 성능 향상을 위해 트리거, 검증 규칙, 워크플로우를 일시적으로 비활성화합니다.
- 일일 한도에 도달하지 않도록 Salesforce API 사용 한도를 모니터링합니다.
- 전체 배포 전에 소규모 데이터셋으로 테스트 임포트를 수행합니다.

**시나리오: 커스텀 사용자 역할을 위한 새 페이지 레이아웃을 배포했지만 사용자들이 여전히 이전 레이아웃을 봅니다. 무엇을 확인하나요?**

- 새 페이지 레이아웃이 올바른 프로필에 할당되었는지 확인합니다.
- 레코드 타입(record type)이 새 페이지 레이아웃에 매핑되었는지 확인합니다.
- Lightning Record Page가 레이아웃을 재정의(override)하고 있는지 검증합니다.
- 필드 수준 보안을 살펴 필드가 표시되는지 확인합니다.
- 사용자로 로그인해 페이지 레이아웃을 확인하며 테스트합니다.

**시나리오: 새 Visualforce 페이지를 배포했지만 사용자가 접근 시 오류를 받습니다. 무엇을 확인하나요?**

- Visualforce 페이지가 사용자 프로필용으로 활성화되었는지 확인합니다.
- 업데이트가 필요한 하드코딩된 참조가 있는지 검증합니다.
- 페이지가 컨트롤러를 사용한다면 Apex 클래스 권한을 확인합니다.
- 디버그 로그를 살펴 정확한 오류 메시지를 확인합니다.
- 다양한 사용자 역할로 페이지에 접근하며 테스트합니다.
